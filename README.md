## 0.15.0 AirPlay 独立原生队列

用户真机反馈 0.14.0 连播仍卡住，本次删除与手机播放器共用实例的投屏实现，改用独立 iOS 系统播放器和原生队列。提前准备并入队下一集，切集不经过手机结束事件或页面重新安装；关闭先停止并撤下队列，再释放中转和准备文件。手机播放器保持独立，系统仍选着电视时暂停手机，切回 iPhone 后按实际分集、进度和暂停意图恢复。参考 app 实现的是同款 app 间局域网推送，并没有 AirPlay。完整说明见 [重做记录](docs/airplay-native-queue-2026-10-04.md)；安卓接收软件仍需真机验证。

## 0.14.0 AirPlay 会话重构（已由 0.15.0 替换）

将系统音频路由、外部视频状态和单集媒体生命周期分开管理。换集直接替换视频，保留电视连接；新视频安装完成后才关闭旧中转。退出先停止并释放原生媒体，再清理中转和临时文件。再次进入先读取系统真实路由：仍选中电视时，从第一集的准备阶段就使用电视可访问的地址；在 AirPlay 中选择 iPhone 后恢复本地视频、进度和暂停状态。仅音频连接不能显示视频已连接，视频未接通会明确暂停并提示，不再进入通用恢复循环。真机接收软件仍需复测，见 [重构记录](docs/airplay-session-rebuild-2026-10-04.md)。

## 0.13.2 AirPlay 连播与手机播放

AirPlay 在后台收到播放结束后直接切换下一集，回到前台同步页面，遵守自动连播开关和最后一集边界。普通播放器默认在本机播放，只有准备好电视可访问的视频地址后才启用外部视频；不让旧系统路由或迟到回调把新的手机视频送给电视。补齐按播放器实际进度确认结束的兜底，保留重播与原有画中画行为。范围和验证见 [修复记录](docs/airplay-continuation-2026-10-04.md)。

## 0.13.1 投屏取流与启动修复

AirPlay 改为先准备电视可访问的视频地址，再打开系统设备列表；解密后的本地视频和带请求头的在线媒体经过局域网中转。保留当前进度、暂停状态和切集，系统回报投屏状态时显示已连接；修复进入后台被播放器主动暂停的问题。安卓电视接收软件的实际兼容性仍需真机验收。

投屏中转优先使用 Wi-Fi 地址，DLNA 按电视控制连接选择可用网卡；补齐本地 MP4 的文件尾部读取、HEAD 探测和 DLNA 媒体描述。等待电视准备播放后再定位，暂时未就绪时有限重试，取消或超时停止后续加载命令。失败提示区分电视未读取视频、视频传输失败和已读取但未确认播放。范围与真实 HTTP 验证见 [修复记录](docs/cast-transport-2026-10-04.md)。

## 0.13.0 投屏会话与续播

投屏控制面板可以收起和重新打开，电视继续播放；播放器显示返回投屏控制的入口。按选择电视时的手机实际进度和暂停状态开始，投屏期间暂停手机并锁定本地切集／拖动，结束时读取电视最终进度再交回手机。状态读取失败保留已确认位置，电视未确认结束时保持手机暂停并允许重试。在线媒体和已完成的本地 MP4 共用该流程。范围与验证见 [实施记录](docs/cast-session-handoff-2026-10-04.md)。

## 0.12.1 记录保存优化

观看位置、分集、时长和剧集资料不变时跳过保存及通知，保留原观看时间；位置变化、切集和实际时长更新仍按播放器原有时机保存。记录与目录／分集缓存改为独立文件和写入队列，保存进度不再重新整理整个剧库。未变化的历史条目复用 JSON 数据，旧数据渐进迁移；缓存损坏可重新加载，观看记录与已读基准独立保留。范围和验证见 [实施记录](docs/record-storage-2026-10-04.md)。

## 0.12.0 新季提醒与同系列

## 使用方式

- 点击当前站源打开网格，支持搜索站源名称；剧库按十六站分别浏览，收藏、历史和下载支持“全部站源”筛选。
- 选集、上下滑切集、续播、倍速、画中画；单击切换控件，左右滑动预览进度，长按 2 倍速，长按后左右滑动快进/快退。
- 榜单采用大封面与排名卡片；黄果、黄豆以及历史/下载记录会自动补取缺失或过期的封面。
- 浅色、深色、跟随系统，手机与平板布局。
- 分集与整剧下载、直接播放、滑动删除；按剧统计空间和大小排序，跨状态整剧多选删除，按失败/暂停状态筛选与批量重试；离线浏览、记录备份与导入。
- iOS AirPlay；Google Cast、DLNA 设备发现、在线／本地投屏及结束后的进度交接。投屏期间保持应用前台。
- 站源解析嵌入应用内，不需要部署电脑或业务服务器。

## 安装 iOS 开发版本

1. 打开本仓库 [Releases](https://github.com/maxduke/guoguo-mobile/releases/latest)，下载对应版本的 `Guoguo-版本+构建号-ios-unsigned.ipa`。
2. 可使用同页 `SHA256SUMS` 核对文件完整性，`build-info.json` 可查询源码提交与构建记录。
3. 使用自己的签名工具和 Apple 账户重新签名后侧载到 iPhone / iPad。

未发布的开发构建仍可在通过的 `CI` 运行中下载 `Guoguo-iOS-unsigned` artifact，保留 14 天。Release 附件不受该保留期影响。

IPA 未签名，不能直接点击安装。签名工具、账号与证书均由使用者管理，不存入仓库。自签后需实测本地网络发现、画中画及后台下载。

## 发布新版

1. 更新 `pubspec.yaml` 中的版本和递增构建号，新增 `releases/v版本.md` 更新说明。
2. 提交并推送源码，等待该提交在 `main` 上的 push CI 检查和 iOS 构建通过。
3. 对同一提交创建并推送版本标签，例如 `git tag v0.3.0`、`git push origin v0.3.0`。
4. 标签仅触发 `Release` 工作流：查找同一提交已成功的 `main` push CI，复用其 IPA，核对版本、提交及 SHA-256 校验和后发布；不重复测试或 iOS 构建，上传完成前保持草稿状态。

若标签先于 CI 完成，待 CI 成功后重跑失败的 Release；若构建产物已超过 14 天保留期，先重跑该提交的 main push CI，再重跑 Release。不会回退到其他提交的安装包。

标签必须匹配源码版本，安装包内部版本及构建号也必须一致。普通分支、PR 和手动 CI 运行不会发布；失败运行可重试，已公开版本的附件不会自动覆盖。发布标签不应移动或复用，修复已发布版本时递增版本号。

## 本地开发

工具版本与 CI 对齐：Flutter 3.47.4、Go 1.27.1。iOS 原生编译需要 macOS、Xcode 和 CocoaPods。

```bash
flutter pub get
scripts/setup_core.sh
scripts/build_core.sh ios
flutter config --no-enable-swift-package-manager
scripts/prepare_ios_media.sh
python3 scripts/prepare_ios_player.py
flutter build ios --release --no-codesign
```

`prepare_ios_media.sh` 在构建时准备依赖包提供的原生 FFmpeg 库；应用运行时不会下载或启动桌面可执行文件。

`prepare_ios_player.py` 校验锁定的播放器源码并生成仅供 CocoaPods 使用的 iOS 修复副本，依赖缓存保持原样；Podfile 也会在安装依赖时准备该副本。当前 iOS 构建使用 CocoaPods，保持 Swift Package Manager 关闭。

Android 暂未完成验收。配置 Android SDK/NDK 后可使用 `scripts/build_core.sh android` 构建桥接库。
