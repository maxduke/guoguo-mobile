# 红果取流修复与 hongguo-drama 对照（2026-11-08）

用户确认最新版 iOS 的红果仍无法播放。本轮固定参考 [jackotom/hongguo-drama b2b81ce](https://github.com/jackotom/hongguo-drama/tree/b2b81cec61159ae788c723b21ad1015ac40296f6)，重点读取 `src/native/app-source.js`、`playback-device.js`、`hongguo.js`、5.4 发行说明、内联模型恢复说明及 issue #91 的实际观察。该项目是 Electron 桌面应用；桌面发行验收不能替代我们自己的 iOS 验收。

本轮协议与身份策略取代 [11 月 2 日的共享身份恢复策略](hongguo-identity-recovery-2026-11-02.md)。以前的联网记录只证明当时行为，不能继续作为当前接口不需要签名的依据。

1. 修改前，移动 API 探针取得 18 条推荐、20 集详情，但 App 模型请求在旧身份恢复后仍为空，网页和第三方备用路径也未成功。日志：`/tmp/guoguo-hongguo-drama-before.log`。
2. 对同一部剧 `7569107801272765465` 的同一集，各自新注册匿名身份，并限定一次模型请求：无签名失败，签名成功。除签名及对应地区头外保留相同本地设备资料和请求体；该对照证明请求头组有影响，不能单独区分每一个签名头与地区头的作用。日志：`/tmp/guoguo-hongguo-drama-control.log`。
3. 同剧连续三集：共享已注册身份的第 1 集成功，第 2、3 集空响应；第 2 集换新身份立即成功。这在本机重现了 [issue #91 的单次身份观察](https://github.com/jackotom/hongguo-drama/issues/91#issuecomment-6590160496)，但不等于平台公开承诺所有设备都采用同一配额。日志：`/tmp/guoguo-hongguo-drama-identity.log`。
4. 修复后的同一个 `MobileClient` 连续三次 `resolve` 均取得加密媒体。日志：`/tmp/guoguo-hongguo-drama-sequential-final.log`。
5. 《浴火之路》`7631046819190934553` 的 58 集详情与首集媒体读取成功（HTTP 206，1024 字节），完整 CENC 解密、MP4 准备与 FFmpeg 全集解码成功。此次完整解码在签名修复后执行，随后身份作用域与缓存修改通过连续三集移动 API 和回归覆盖。日志：`/tmp/guoguo-hongguo-drama-decode.log`。

探针使用临时目录，不读取用户账号，不把设备 ID、Cookie、签名媒体地址或密钥写入这些结果日志。临时对照程序不进入默认测试套件。

## 本地修改

- 播放依然匿名，但按最终 query、实际序列化 POST 正文、注册身份及本次时间计算完整签名。换官方主机、批量退回单集、替代身份都重新签名；地区头使用 `cn` / `did`。注册接口继续使用其独立二进制校验协议，目录、详情、搜索与评论保留各自协议。
- 每次未命中缓存的取流任务独立注册身份，重试只复用本任务身份。不同任务不再共享一个可能已被使用的设备；也无需维护跨任务的身份版本、失败轮数和轮换锁。并发与取消不再把其他任务带入同一身份状态。
- 注册受 8 秒子期限和原移动请求总期限约束；注册失败后后续任务冷却 10 秒，调用方取消不触发冷却。拒绝响应即使携带数字 ID 也不被接受。冷却不代表上游已经解除限制。
- 普通轮次最多四次官方取流，只有前台完整全空时允许额外注册一次并再试一轮，最多两次注册、八次模型请求；后台模型预取保留单轮预算。业务错误、格式错误、4xx 与限流不触发身份恢复。
- 已取得的后续分集模型继续按集复用，不因其他任务注册而清空，也不会为缓存命中注册身份。缓存仍最多六条、两集前瞻、最长一分钟、用后移除；新增 `expire_time` 上限和五秒交接余量，失效或不可信到期字段不进入缓存，取消的请求不回填缓存。

`provider_hongguo_device.go`、`provider_hongguo_app.go`、`provider_hongguo_native_media.go` 和 `provider_hongguo_model_cache.go` 是主要入口；来源和 GPL 声明见 [UPSTREAM.md](../native/core/UPSTREAM.md)。

## 值得吸收的改进

| 参考做法 | 本地情况与决定 |
| --- | --- |
| 最终请求签名、按取流任务注册身份 | 本轮采用，已有同集对照和连续切集证据。继续使用我们已验证的签名算法和一致设备资料，不复制参考项目不同接口之间的混合版本。 |
| 注册失败冷却、尊重播放模型到期时间 | 本轮采用。限制反复注册，避免预取交给播放器的地址已经过期；不扩成六小时媒体缓存。 |
| 模型缺解密资料时有条件读取 `fallback_api` | 后续优先级最高。当前解析没有这条恢复路径；需要同时补齐内联加密标记校验，并校验同一视频身份、完整时长差不超过 0.5 秒、实际尺寸不降低、密钥和固定域名。它针对有效 JSON 缺资料，不能修复空正文；本轮实际成功样本无需该接口。参考 [实现说明](https://github.com/jackotom/hongguo-drama/blob/b2b81cec61159ae788c723b21ad1015ac40296f6/docs/inline-playback-metadata-fallback.md)。 |
| 拒绝后暂停待开始的下载队列 | 适合后续核对我们的下载调度，避免同一服务拒绝后每集重复失败。不能把桌面项目的约百集限制当作我们的已知固定阈值；先按实际错误种类建立队列回归。 |
| HTTP 状态、响应字节数与请求追踪号诊断 | 值得接入已有诊断日志，帮助区分空正文、注册拒绝和解码失败。我们已有日志系统，无需新建遥测服务；不记录账号、设备 ID、密钥和完整 URL。 |
| ByteVC2 软件转换与跨任务转换队列 | 暂不移植。我们已有 FFmpeg/CENC 准备和预取接管，但现有移动解码器不支持 ByteVC2；参考项目额外携带桌面转换运行时。需单独验证 iOS 二进制、包体、CPU/发热、后台执行与许可证，再判断产品收益。继续保留 H.264/HEVC 与 `device_level=1`。 |
| 后续两集预取、取消与前台接管 | 我们已有相应机制，保留并验证；不重复引入桌面状态层。 |

## 验证与边界

回归覆盖最终 query/正文签名、重试保留本任务身份、连续任务身份分离、并发隔离、取消、注册失败冷却、拒绝带 ID 的业务失败、前后台恢复预算、预取缓存与到期时间。签名仍通过既有 14 组独立上游 oracle 向量校验。

最终 `go test ./... -json -count=1` 共 715 个测试/子测试通过、零失败；8 项既有可选联网巡检未启用。FFmpeg/CENC 回归实际执行。`go vet ./...`、身份/并发/取消/恢复/缓存的竞态检查、格式与差异检查通过。最终 Go、竞态和静态检查日志分别是 `/tmp/guoguo-hongguo-drama-go-final.jsonl`、`/tmp/guoguo-hongguo-drama-race.log`（并以 `/tmp/guoguo-hongguo-drama-race-final-targeted.log` 补查最后修正的两个用例）和 `/tmp/guoguo-hongguo-drama-vet.log`。本轮没有修改 Flutter 页面或依赖，也未生成发布包。上述主机 API、真实媒体和解码验证不代表 iPhone 已通过起播、切集、PiP、后台恢复与长时间连播；需要安装修复构建验收。服务端注册拒绝、限流或网络变化仍可能导致失败。
