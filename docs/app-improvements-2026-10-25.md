# 可靠性修复与 Android／TV 交付

基于 v0.19.10+50，落实[发布后审查](app-review-2026-10-25.md)中有证据的缺陷及重复工作，准备 v0.20.0+51。当前是否已发布以 Release 为准。

## 行为与数据保护

- **观果**：接入 H5 详情和逐集取流，校验作品 ID、集数、分集序号及加密信封；分集缓存只保留稳定身份，播放时刷新地址。保留供应方画质顺序，不臆造分辨率标签。真实主机抽查返回 30 条目录、81 集，所选集 MP4 首段为 HTTP 206、1024 bytes；这不是整集解码或设备起播证明。
- **备份**：生产导出使用有体积上限的紧凑 UTF-8 编码，大备份在 isolate 编码／校验；30,000 条近限制记录可导出再导入。超过 20 MiB 明确拒绝导出，不截断记录。导入立即占据记录事务顺序，候选资料落盘成功后才安装，外部可变元数据不会跟随导入改变。
- **下载恢复**：格式损坏时提供检查、导出原件和确认修复入口。先保留原始字节，再恢复可识别条目；重复／不安全条目隔离，未知目录及预览后出现的目录继续保留。保存后的保护标记跨重启生效；未完成的可识别任务按原网络规则恢复下载。不会把“跳过错误行”当作安全的自动孤儿清理。
- **增量进度**：拆出下载条目与任务事件归并；每任务保留最新状态／进度，300 ms 合并后只更新受影响条目。启动、前台恢复、显式刷新及完成整理继续做完整核对。进度达到 100% 后仍等待原生完成状态，再开始视频整理。回归确认 80 次进度事件不触发整组数据库快照；刷新进行中到达的事件不会丢失，删除／重试会清除旧事件缓存。
- **隐藏页面**：追剧／下载页面隐藏时暂停展示订阅与动画，返回后一次读取最新数据；保留页面状态及失效的播放意图规则。200 条下载的回归样本在隐藏时收到进度通知，条目读取次数为 0，返回后能显示新增的第 201 条。

## Android 与电视

新增 Android CI，生成包含 ARM 32 位、ARM 64 位和 x86_64 的 APK，最低 API 24。修复本地 gomobile AAR 被新版 AGP 拒绝的问题，插件包含 Java bridge、JNI 库及生成的 ProGuard consumer rules，防止 release 缩减时破坏 JNI 名称。

正式包使用项目固定签名，缺少签名时拒绝 release 构建。开发包使用独立的 `.dev` 应用 ID。包检查覆盖版本／构建号、TV 启动入口和横幅、签名及固定证书指纹、三 ABI、Go bridge 类、包内核心源码／版本标识、ZIP 对齐与 64 位 ELF 的 16 KB 对齐；元数据和 APK 有各自校验和。

电视通过原生系统模式识别，加入侧栏、大控件与焦点边框；方向／确认完成导航，播放页支持控制条、十秒定位、媒体播放暂停和相邻集键。隐藏页面和隐藏播放控件不参与遥控器焦点移动。手机和平板继续使用原有导航。

已构建 v0.20.0+51 固定签名正式 APK，并通过本机静态包校验：应用标识与最低 API、电视桌面入口与横幅、固定签名证书、三 ABI 的 Go 核心版本和源码摘要、JNI 类、ZIP 对齐及 64 位原生库 16 KB 段对齐均匹配。该包尚不是 CI 产物；PR HEAD 的 CI 结果随交付记录核对。Flutter 遥控器导航、焦点、确认打开和明确播放／暂停语义测试通过，并生成浅／深色电视布局预览。预览使用合成内容，不是来源实测截图。

主机磁盘余量不足以安装 Google TV 模拟器及保留构建空间，因此没有模拟器或真机验收结果。盒子解码、系统遥控器映射、真实起播、后台下载、PiP 和持续播放仍需设备检查，见 [Android／TV 说明](android-tv.md)。

## 维护与验证

- 封面诊断区分原生请求失败、响应字段失败和 Flutter 图片解码失败。设置中的站源诊断可检测当前剧库首张封面；输出不包含 URL、密钥、Cookie 或异常原文。没有改动代理、DNS 或证书验证策略。
- MobileClient 退出时取消在途请求；Android 插件按引擎保留独立 session，迟到回调不会返回到新引擎，旧 session 关闭不会影响新实例。
- 巡检可选择解析一个分集，检查 HLS 清单、AES-128 密钥和媒体首段；也覆盖无扩展名清单及 HTML 伪视频。摘要与附件上传分离，上传失败不丢失摘要。结果仍为提示，不能据此自动停用来源；周期任务在新工作流合并后恢复启用。
- 本地 Go 全套、针对修改模块的竞态检查和 vet 通过；Python 发布／工作流与 Android 包契约检查通过。Flutter 功能、数据事务、真实 FFmpeg、遥控器及布局回归已执行；额外启用的性能测量用例补齐缓存关闭收尾并定向复验通过。最终源码检查、iOS 与 Android 构建以同一 PR HEAD 的 CI 为门槛。

黄果保持现状；帝果继续启用；皮果、牛果、超果和爽果继续默认停用。真实目录工作集／设备负载仍待采样，本轮没有凭行数拆分整个 CatalogStore／PlayerPage，没有替换播放器、数据库或全局状态框架。现有请求的外层预算仍为有界时限；未测出普通负载下的排队故障，不将其误报为已确认卡死。
