# 站源诊断与剧库提前加载

本轮目标是让刷新故障可定位，并在明确的页面和网络边界内提前加载剧库下一页。它不改变媒体预取、分季续搜或播放器行为。

## 请求诊断

`AppStore` 使用独立的 `SourceDiagnostics`，通过 `ObservedProviderClient` 观察目录、分类、栏目、推荐、搜索、联想、详情和分集 API。原生协议仍为 3，`coreInfo` 提供可选能力标记；旧核心缺少统计时显示未知，不将零联网尝试推断为缓存。

原生上下文携带线程安全计数，在实际 HTTP 客户端调用前计数联网尝试，取得响应时记录状态码；原生栏目及红果搜索/详情的明确结果缓存、共享结果请求分别计数，应用端推荐/栏目、搜索和分集缓存读取也单独记录。一次逻辑 HTTP 尝试可能含内部重定向、DNS 或连接重试，不是抓包计数，也不能证明站点收到请求。API 返回 warning 或 stale 记录为部分结果；取消、DNS、超时、限流、浏览器验证等使用固定类型。

0.19.1 的类型化读取在同一次观察内执行原有解析器，仅解析一次、仅记录一次；不添加原生请求字段。`requestResult` 保留核心请求结果，应用端缓存读取标记 `not_requested`；`validation` 区分 `not_checked`、`passed`、`failed`，`result` 表示该 API 最终结果。返回内容校验失败时标记 response 阶段，并保留该请求的联网次数、缓存/共享计数和 HTTP 状态。直接 raw 调用、缓存读取或未取得有效响应时不声称做过本轮内容校验。旧核心字段仍能读取，缺少新增字段时按未校验处理；复制格式版本仍为 1，新增两个固定枚举字段。

分类、剧库、搜索、推荐、栏目、详情和分集使用同一组固定错误提示，优先采用核心失败类型，旧核心沿用已有安全提示。原始异常文本不进入这些提示。详情、分集的目录缓存保存失败沿用独立缓存告警，保留已经装入的有效结果；记录保存失败继续单独上报并保留原有事务契约。诊断的内容校验通过仅表示 API 资料可解析，不代表保存或媒体播放成功。

每端仅保留最近 64 条，应用端不写盘。失败通过对应 traceId 查询已完成诊断，不覆盖原错误。复制内容只有固定来源/操作/状态、时间、整数计数、页码及刷新/后台标记；不包含搜索词、剧名、剧集 ID、URL、请求头、凭据或异常原文。晚到计数和关闭后的记录不安装。

## 受控预取

独立偏好 `catalogPrefetch` 默认开启，Wi-Fi 状态未知、检测失败或非 Wi-Fi 时不启动。仅当前可见剧库、应用前台、默认顺序且距离尾部不超过 1.5 屏时，在 350 ms 停稳后尝试当前分类下一页。每次停稳最多一页，避免短列表无限自动填充。

一个 `CatalogStore` 同时只持有一个预取。低优先级原生请求等待前台请求完成，拥有独立 requestId、来源、分类和页码，并限制为八秒。切换条件或手动刷新立即取消本地等待和对应原生任务，不等待旧网络结束；仅原任务所有者、相同 slice 和未变更页码可以安装结果。警告、失败及无效结果不推进页码、不显示前台重试错误；三十秒后允许再次尝试，手动加载不受该退避阻塞。

十六个远程分类源拥有明确页码，可以安全丢弃结果并重复请求同一页。红果、黄果和黄豆的聚合目录会推进持久游标，不能仅丢弃结果来取消预取，因此仍按需加载。米果目录实际为单页，hasMore 为 false 后不发起预取。目录落盘失败沿用已有缓存错误处理，不将已安装的有效页误判为网络失败。

## 十九源文本巡检

从 `sourceCapabilities` 取得真实能力，每源使用全新临时目录和核心客户端。并发上限为两源，每次 API 最长十二秒、整轮五分钟；预算耗尽的步骤明确标记 skipped。检查分类（如支持）、冷目录、栏目列表、强制刷新一个栏目及立即缓存复读、搜索、目录中第一个作品的详情与分集。黄果检查全部三个栏目；黄豆的搜索标记 local_filter，应用内本地筛选由 Flutter 回归覆盖。合法空搜索可以通过，空默认目录、缺失字段和身份不符不能算可用。

```sh
cd native/core
go run ./cmd/sourcecheck -output /tmp/source-check.json
go run ./cmd/sourcecheck -sources huangguo,hongguo -output /tmp/source-check-focused.json
```

报告只含来源、操作、计数和安全状态，不输出内容资料或原始错误。不请求封面、取流或视频。`.github/workflows/source-check.yml` 每日及手动独立运行，产物保留七天；站点失败写入报告而不阻塞构建，工具初始化/报告写入错误仍使该工作流失败。排查必须查看 JSON 内的 failed/partial/skipped，绿色工作流只表示巡检执行完成。

这是一轮环境相关的文本样本，详情/分集仅取一个作品。它不证明全站、所有分类、实际播放、设备性能或持续可用率。

## 验证与设备验收

回归覆盖诊断关联、统计边界、固定输出结构、记录上限、实际 HTTP 路径；预取安装、刷新接管、分类取消、晚到丢弃、错误退避、停稳预算与未知网络；Wi-Fi 快照/事件竞态和关闭后的完成回调。

0.19.1 回归覆盖冷/旧缓存下自动及手动分集刷新、缓存保存失败后的有效结果和提示、记录失败仍可观察、九类 API 的类型解析失败、部分响应、旧字段及旧剧集 ID、反序完成时的统计隔离，以及跨分类/剧库/搜索/详情/分集的固定原因提示。

剧果访客授权共享请求保留取消/超时类型：预取所有者被取消时，等待它的前台操作可以重新取得授权，而非继承旧任务的失败。确定性并发回归覆盖该接管路径。

设备上分别验证 Wi-Fi、蜂窝、断网、关闭开关，滚动后观察下一页、切源/分类、返回与后台取消；手动刷新立即开始且旧结果不回填。清缓存后刷新黄果三个栏目，再复制诊断核对联网与失败类型。设备结果在取得反馈前保持待验收。
