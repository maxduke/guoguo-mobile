# 投屏取流与启动修复（2026-10-04）

版本 `0.13.1+30`。用户确认首次真机失败使用 AirPlay 投到安卓电视接收软件。本批补齐 AirPlay 媒体交接，同时修复调查中复现的 Google Cast／DLNA 中转缺陷；接收软件名称、版本和电视错误尚未提供，实际根因和兼容性仍需真机核实。

## AirPlay 媒体交接

原入口仅展示系统路由选择器，提前开播时只能先转完整视频。本地解密视频仍使用手机文件 URL，带认证头的在线视频没有为接收器提供可独立取流的地址。根据 [WebKit 的 AirPlay 地址说明](https://webkit.org/blog/15036/how-to-use-media-source-extensions-with-airplay/)，共享视频需要接收器可以使用的媒体地址。本批对完整本地 MP4 和在线媒体使用带随机令牌的局域网中转；HLS 清单、片段和密钥继续使用原请求头取流。提前开播先完成兼容准备，不把 loopback 播放清单交给电视。

播放器按钮先安装中转 URL、保留当前时间／倍速／暂停意图，再通过同一个 AVPlayer 的原生桥接清除本地视频合成并打开 AVRoutePickerView。设备列表由 iOS 系统处理；以视频设备优先，保留 iPad 展示锚点。准备后关闭列表或切回 iPhone 保持中转有效，重开列表不重复安装和定位；切集更换资源，已连接时直接准备新集而不重新弹出设备列表。退出播放器释放中转，旧请求不能覆盖新集。

已确认原生播放器进入后台后会在未启用 PiP 时主动暂停，没有检查 AirPlay。本批在原生后台判断中排除外部播放，观察 AVPlayer 的实际外部播放状态并按播放器标识传回 Flutter；Flutter 生命周期允许该 AVPlayer 在 AirPlay 中保留控制，避免按本地卡顿执行恢复。Google Cast／DLNA 仍保持手机暂停的原策略。后台播放配置沿用已有 audio 模式；[Apple AirPlay 集成说明](https://developer.apple.com/videos/play/wwdc2019/501/) 要求正确配置音频会话和后台模式，但最终持续取流仍需接收软件实测。

## 已证实的缺口

- 原中转从第一块私有 IPv4 网卡选择地址，可能选中 VPN 或蜂窝网络。本批排除虚拟／蜂窝接口并优先 Wi-Fi；DLNA 使用电视控制端的实际连接路由选择对应本地地址，路由探测失败则沿用 Wi-Fi 选择。Google Cast 插件的 Dart 设备模型没有暴露接收器地址，使用 Wi-Fi 优先策略。
- 原本地文件仅识别 `bytes=起点-终点`。真实 HTTP 测试确认 `bytes=-8` 返回 416，修正后返回正确的末尾八字节和 206。实现闭区间、开放尾部、后缀和大整数边界；416 含总大小，HEAD 忽略 Range 并返回完整文件信息。多范围／未知范围单位可返回完整内容。依据 [RFC 9110 Range 规则](https://www.rfc-editor.org/rfc/rfc9110.html#name-range)。
- 原 DLNA `CurrentURIMetaData` 为空。[索尼官方播放示例](https://github.com/sonydevworld/audio_control_api_examples/blob/master/DLNA/AVTransport/play_file.adoc) 说明部分接收器需要媒体描述。本批用 DIDL-Lite 提供名称、视频媒体类、资源 URL、容器类型和已知时长，按 XML 规则转义；本地完整 MP4 使用 MP4 类型，在线 HLS 使用 HLS 类型，不假报编码或设备支持能力。
- 原 DLNA Play 后立即 Seek，尚未准备播放时会失败。本批在支持状态读取的接收器上短暂等待开始播放；不提供状态时沿用 Play 动作响应。Play／Seek 仅对 701 暂时无可用状态有限重试，每次间隔 500 ms、最多五次，其余错误立即失败。读取明确持续停止状态时报告未开始播放。依据 [UPnP AVTransport:1](https://upnp.org/specs/av/UPnP-av-AVTransport-v1-Service.pdf)。

## 失败与清理

SOAP Fault 即使通过 HTTP 500 返回也保留 DLNA 错误码，避免把 701 暂时未就绪和不支持定位等错误混为一谈。整体加载仍受会话超时限制；取消、失败、超时和页面销毁时先中止后续加载／重试，再尝试结束接收器，迟到进度不能接管手机。

中转记录有效媒体 GET、发送字节和经过清理的源错误，不收集媒体地址、凭证或密钥。手机展示连接、准备传输和等待电视播放阶段；失败时区分未取流、源拒绝／传输中断，以及已读取但未确认播放。读取数据仅证明传输过程，不等于电视解码成功。停止失败继续保持手机暂停和重试入口，保留上版进度交接行为。

文件发送提供 DLNA Streaming／字节定位响应头和 CORS；在线中转要求 identity 编码，避免压缩改变字节范围含义。HLS 主清单、变体、初始化片段、密钥与媒体片段继续通过注册资源中转，保持原请求头和私有资源边界。关闭接收器 HTTP 探测连接不会留下未处理异常。
