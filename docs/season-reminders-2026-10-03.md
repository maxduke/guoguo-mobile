# 新季提醒与同系列（0.12.0+27）

用户确认 0.11.4 真机测试无明显问题后，继续实施红果新季提醒及详情页同系列联网补全。本批不改变播放器和媒体协议。

## 行为

- 红果详情先显示目录、搜索缓存、收藏、历史和已有提醒中的同系列作品，不自动联网；“联网补全”复用现有可取消的渐进搜索。
- 只匹配同一来源、规范化后的同名系列。支持中文／数字季号、全角数字、空白及末尾标点，季号限定 1–200。“季”和“部”分别匹配；无季号的标题只有在单位明确时按第一季处理，不推测有歧义的系列。
- “提醒新季”是独立开关，不修改收藏和观看历史，不引入想看／在看／已看状态。开启后立即尝试建立基准；离线开启时待下次检查。
- 第一次完整成功结果中已有的更高季作品作为已知基准，不提示为刚发现的新季。警告、截断、尚有后续页的结果不建立基准。基准建立后新发现的更高季作品保持未读；部分失败或结果暂时缺失不删除已知作品，也不重置已读状态。
- 追剧页“检查更新”沿用收藏新集检查，同时检查独立开启的新季提醒。提醒可在没有收藏的情况下使用；同系列同单位的提醒复用一次检查结果，结果保留查询锚点，避免不同季间遗漏。
- 打开新季详情后标记该季已读，其他新季保留；关闭再开启提醒重新建立基准。没有系统通知或后台定时检查。

## 请求与数据边界

单次同系列请求最多读取三个搜索页，限二十秒，最多展示二百部作品；达到页数或结果限制时明确保留未完成状态。请求使用独立 ID，不进入最近搜索，不与其他页面共享取消所有权。返回、切换作品、开始播放、后台及结束所属检查时取消；迟到结果不进入缓存、目录或提醒。原生搜索进度轮询不重叠，取消后停止轮询。

提醒只使用标题匹配，不宣称是站源官方关联或个性化推荐。手动检查跳过 Dart 搜索缓存，但仍受 Go 和上游缓存时效影响，不承诺刚上线的新季即时出现。

提醒保存在记录区，每个锚点最多二百个已知新季。带提醒的记录备份采用 `guoguo.records` v2，保存基准、作品资料、已读和更新时间；v1 仍可载入及合并，不凭旧收藏自动开启提醒。没有提醒时仍导出 v1。合并按提醒更新时间选择较新的一份，保存失败回退本次修改，不覆盖期间的新提醒状态。完整备份校验后才修改现有记录。

## 验证

本地分批覆盖 73 项 Flutter 回归，其中 31 项为新功能用例；包括标题与单位隔离、首次基准、部分失败、已读及重启、v1／v2 备份和保存失败、迟到结果、独立取消、分页／时间预算、进度轮询，以及详情和追剧入口。另有 16 项 Python 工具回归、静态分析、格式及版本检查。iOS 编译交给本批 PR CI，不把模拟界面视作设备验收。

设备复核见 [iOS 清单](ios-device-checklist.md)。
