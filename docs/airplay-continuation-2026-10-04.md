# AirPlay 连播与手机播放修复（2026-10-04）

版本 `0.13.2+31`，接续 `0.13.1+30`。用户确认单集投屏已能播放，但不会自动下一集，之后手机视频持续提示恢复失败；接收软件名称及退出／重启后的具体情况尚待补充。

## 已复现的问题与修正

新增 Flutter 回归在旧代码上复现三项失败：未准备的播放器采用遗留系统路由、AirPlay 结束事件在后台被忽略，以及旧路由使下一次普通手机切集误走中转。此前测试手动切集通过，没有覆盖自然播完后后台自动切集，这是本次补齐的缺口。

AirPlay 自然结束时允许在后台继续自动下一集，通过播放会话直接激活，不等待不可见 PageView 的动画或回调；回到前台同步选中页面。保留自动连播开关和最后一集的停止行为。新集继续先准备完整媒体，再安装电视可访问的中转地址；设备列表不重复打开。

上版原生 AVPlayer 默认允许外部播放，系统路由可能超出单个播放器的生命周期。新播放器及换源先关闭外部视频，安装可供电视读取的 HTTP(S) 地址后才重新启用；原生拒绝文件、localhost 和 loopback 地址。Dart 路由状态也必须属于本播放器已安装的 AirPlay 资源，重置后迟到回调不能重新激活。依据 [Apple 对本地播放和 allowsExternalPlayback 的说明](https://developer.apple.com/videos/play/wwdc2019/501/)。这一改动消除代码中已确认的路由污染路径，具体设备的全部失败原因仍需复测确认。

部分接收器遗漏结束通知时，原生位置读取只有在仍有播放意图、媒体状态可播放、完整时长有效且实际位置达到完整时长时才补发结束。不使用时钟估算或靠近片尾就跳集。原生结束入口校验当前媒体，记录已经完成的对象，防止重复／旧媒体结束跳过下一集；重新定位到结束前解除完成标记，重播后仍能正常结束。循环播放继续使用原有路径。

## 验证与限制

回归覆盖后台完成后直接下一集、回前台页面同步、自动连播关闭／最后一集停止、遗留路由不改变普通手机切集、资源重置后迟到回调，以及既有暂停、非零位置、投屏重开和 PiP 后台切集／恢复行为。Swift 策略增加可投送地址和实际结束边界用例，保留既有 HLS 与后台策略；原始依赖与补丁哈希继续校验，未修改共享 pub 缓存。

本地 85 项相关 Flutter 回归通过，静态分析无问题，格式及版本检查通过，16 项 Python 工具回归通过，原生补丁准备校验通过。最终 required CI 验证完整 Flutter／Go、27 项 Swift 策略及 iOS 无签名构建。实际接收软件仍需按 [真机清单](ios-device-checklist.md) 复测；协议模拟和编译通过不等于电视连续播放验收。
