# 五源修复与默认停用（2026-10-25）

本次按用户手机 `0.19.8(48)` 的反馈及[十九源巡检](source-audit-2026-10-24.md)处理五个来源。主机网络与手机代理分流不同，主机通过不等于真机通过，主机连接失败也不等于来源已关停。

| 来源 | 证据与改动 | 当前状态 |
| --- | --- | --- |
| 帝果 | 手机能播放、全部封面缺失。封面已有正确来源 Referer，本次将其 User-Agent 与该来源的页面和播放请求统一。 | 保持启用。主机无法连接站点，尚不能确认封面问题已修复，也未确定代理是否为原因。 |
| 皮果 | 干净会话仍返回 HTTP 403 浏览器验证，既有浏览器兼容连接未能取得可用目录。 | 默认停用，保留手动恢复。 |
| 牛果 | 目录和分集可用，但主解析服务 DNS 失败、备用服务 EOF；正常请求预算下也无法取得媒体。 | 默认停用，等待经过验证的新解析服务。 |
| 超果 | 详情已改成账户和点数播放，五个样本均没有旧式媒体直链。 | 默认停用。本次未调用扣费接口或新增账户功能。 |
| 爽果 | 手机无法加载目录；主机搜索返回验证页。复用既有 Chrome 浏览器兼容连接，来源能力和 UI 均改为本地搜名，避免搜索验证导致整个来源退避。 | 默认停用，手动恢复后进行真机验收。主机目录、详情和媒体探针已通过。 |

## 用户偏好与记录

- 正常选择面板默认隐藏皮果、牛果、超果、爽果；站源管理显示原因，并提供原有的恢复入口。
- 默认策略不写成用户主动隐藏。显式恢复通过 `enabledSources` 保存，重启后继续生效；再次隐藏会撤销恢复选择。
- 旧偏好无需改写。如果保存的当前来源属于这四个且未手动恢复，启动选择回到红果；仍保留四个来源的 ID、收藏、观看记录、下载记录和缓存。
- 搜索站源名称或记录筛选仍可定位来源。默认停用是正常入口的可用性策略，不删除适配器，也不阻断用户主动访问。

## 验证与限制

- Flutter 回归覆盖四个默认停用来源、帝果继续启用、手动恢复和重启、旧偏好回退及收藏保留、管理面板说明和本地搜索。
- Go 回归覆盖帝果封面通过正常 MobileClient 路径携带来源客户端标识；爽果仅 GET/HEAD 导航复用已有浏览器连接，其他来源及 POST 不受影响；能力声明与搜索降级一致。
- 本地全量 Flutter 测试 917 项通过、11 项按环境跳过，运行时指定主机 FFmpeg；Go 全量测试、相关连接与封面路径的 race 检查、`go vet`、`flutter analyze`、Dart 格式检查和差异空白检查通过。iOS 构建与远端结果以本次提交的 PR 检查为准。
- 爽果改动后的主机探针返回 24 条目录、1 集样本及 HLS HTTP 206；独立文字巡检核对本地搜索跳过与详情请求，不把原有搜索退避误判成详情接口失效。
- 封面连接仍执行原有地址、DNS、重定向及证书校验。本次没有改写设备分流规则或强制直连。
- 帝果封面和爽果目录/播放需在手机原代理环境复测。观果新 H5 接口、黄果视频子线路属于独立待办。
