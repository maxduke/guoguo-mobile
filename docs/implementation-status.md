# 当前实现与验证范围

当前行为以 [产品规格](product-spec.md) 为准，状态与资源归属见 [工程边界](app-state.md)。本页只说明验证范围与实际限制，旧版本过程见 [历史实施状态](archive/implementation-status.md)。

## 已有证据

- Flutter 回归覆盖记录事务、真实集号/续播、分页/搜索取消、下载恢复与文件保护、独立状态通知、媒体准备/进度/生命周期、投屏交接，以及布局/操作可达。
- 红果 App 取流回归覆盖 `preload` 请求参数、分集身份、两种播放信息格式、兼容编码、画质和 CENC 密钥。2026-10-16 真实抽查通过推荐、71 集详情及一个分集的取流、解密、整理和整集解码；主机抽查不替代设备播放验收，见 [来源与验证记录](../native/core/UPSTREAM.md#october-16-hongguo-playback-repair)。
- 下一集预缓冲回归覆盖红果完整准备文件没有原生缓冲范围时的触发、换集复用完整文件及进行中任务、后台超时和失败、关闭开关、Wi-Fi 转蜂窝及普通后台取消，以及 PiP 下的完整文件复用、进行中任务接管和关闭窗口清理。真实 FFmpeg 合成 CENC 解密与解码检查通过；实际换集耗时和设备负载仍需真机验证。
- 防熄屏回归覆盖全屏本地播放、缓冲、暂停/重播、切集、前后台、画中画、投屏、错误和退出。原生 FFmpeg 通道模拟连续 64 次准备任务，验证完成回调不累积，启动后可取消，取消等待工作任务结束；已确认的回调泄漏修复不作为真机连播卡顿已消失的证据。
- 已复现 BetterPlayer 重叠播放请求创建多个进度定时器、暂停后仍轮询的竞争。依赖补丁与通道回归覆盖迟到播放/定位/位置响应、慢查询、暂停/切集/退出、同步监听者和连续八十集；实际设备画面掉帧与该问题的因果关系及修复后的负载仍待真机确认，见 [调查记录](playback-polling-lifetime.md)。
- 真实 FFmpeg 媒体回归验证受支持的准备与解码路径，测试构建和模拟事件保留各自范围。
- 当前交付要求 PR HEAD 的 Flutter/core 与 iOS unsigned CI 通过，再确认合并后对应 main 提交的两项检查、iOS 构建及包身份校验。开发下载副本上传失败会明确提示，不替代任何检查；正式发布在标签任务中重新构建、校验并直接上传 Release。具体结果按 [Actions](https://github.com/maxduke/guoguo-mobile/actions) 的提交/运行核对，不能用其他提交的通过记录代替。
- [性能基线](performance-baseline.md) 提供可复现的合成主机样本、原始数据和局部优化结果，不提供设备性能承诺。
- [2026-10-09 站源抽查](archive/upstream-refresh-2026-10-09.md) 记录黄果刷新修复、超果/米果/爽果接入、现有站源结果及浏览器验证限制；当次文本解析成功不等于设备播放验收或持续可用率。

## 仍需设备验收

- [站源诊断和剧库提前加载](source-diagnostics-prefetch.md)：Wi-Fi/蜂窝切换、离页和后台取消，以及手动刷新接管。十九源文本巡检与构建分开，结果仅代表执行环境和采样时刻。

- iPhone / iPad 的签名安装、VoiceOver、系统分享面板、真实分屏、后台下载、PiP 和磁盘不足恢复。
- AirPlay、Google Cast、DLNA 的实际接收设备、连播与结束交接，尤其既有蓝莓接收软件复测。不同协议/接收器不能互相替代验收。
- 冷/热启动、真实起播画面、续播/切集、真实分片队列、主线程暂停、内存及耗电。现有诊断的进度前进是起播近似指标。
- Android 工程保留，完整设备验收尚未完成。

按 [设备清单](ios-device-checklist.md) 记录型号、系统、来源、网络和构建。没有设备结果的项目保持待验收，不由编译或 widget 通过推定完成。

## 当前能力边界

目录/分集缓存尚无新增硬容量限，真实离线工作集和设备负载仍需采样。SQLite、播放器替换、多站搜索预算、跨页面投屏及其他协议队列按 [性能报告中的取舍](performance-baseline.md#当前取舍) 继续评估。高级交换和来源适配保留实际调用与媒体契约，不按代码年龄删除。

缓存无法联网刷新时只能显示已保存资料；站源的实际内容、授权和资源有效性取决于请求结果。下载传输与媒体前台整理分别受系统和设备资源约束，部分文件未完成时不声称可离线观看。
