## 0.13.2 AirPlay 连播与手机播放

用户确认 AirPlay 单集可播放，但不会自动下一集，之后手机播放反复恢复失败。本批复现并修复后台结束事件被挡住及未准备播放器采用旧系统音频路由的问题。后台 AirPlay 直接激活下一集，回前台同步页面；新播放器和换源默认关闭外部视频，只有已准备的 HTTP(S) 视频地址允许启用 AirPlay，文件／loopback 地址拒绝外部播放。原生位置读取到完整时长时补发遗漏的结束事件，过滤重复及旧媒体结束，重新定位后允许重播。接收软件兼容性及真实播放结果仍需用户复测，见 [修复记录](airplay-continuation-2026-10-04.md)。

## 0.13.1 投屏取流与启动修复

用户确认首次失败使用的是 AirPlay 投到安卓电视接收软件。本批补齐 AirPlay 的局域网视频地址与系统选设备交接，保留进度、暂停及已连接时的切集；原生观察外部播放状态，后台主动暂停逻辑排除 AirPlay。播放器本地合成在 AirPlay 准备时清除，迟到的合成回调不能重新覆盖。系统路由、接收器解码及锁屏取流仍待该软件真机验证，不能由自动化结果推定正常。

针对首次真机投屏无法播放的反馈，补齐可复现的中转与 DLNA 启动缺陷：Wi-Fi／接收器路由选址、MP4 尾部 Range 与 HEAD、媒体 DIDL 描述、接收器准备等待和 701 有限重试。取消加载立即阻止后续命令，错误提示结合真实取流情况区分连接、传输和未确认播放。新增真实 HTTP 及解码回归，具体设备失败环节仍需协议、型号和提示确认；见 [修复记录](cast-transport-2026-10-04.md)。

## 0.13.0 投屏会话与续播

投屏会话由播放器持有，控制面板收起后继续播放，可从播放器重新打开。按选择电视时的手机实际进度和暂停意图加载，投屏期间暂停手机并阻止本地切集、拖动和 PiP；结束前读取电视进度，确认结束后将位置与播放意图交回手机并保存到原分集记录。没有实际进度时保留原位置，读取暂时失败保留上次确认位置；结束失败保持手机暂停并允许重试。连接取消、迟到结果、后台返回与发现面板快速重开均有边界保护。范围与验证见 [实施记录](cast-session-handoff-2026-10-04.md)。

## 0.12.1 记录保存优化

观看位置、分集、时长和剧集资料不变时跳过保存及通知，保留原观看时间；位置变化、切集和实际时长更新仍按播放器原有时机保存。记录与目录／分集缓存改为独立文件和写入队列，保存进度不再重新整理整个剧库。未变化的历史条目复用 JSON 数据，旧数据渐进迁移；缓存损坏可重新加载，观看记录与已读基准独立保留。范围和验证见 [实施记录](record-storage-2026-10-04.md)。

## 0.11.4 iOS 提前开播画面修复

针对进度前进但画面停住、拖动后才播放的反馈，修正 BetterPlayer 1.4.1 的 iOS HLS 渲染路径：不再给 HLS 添加 Apple 不支持的视频合成，MP4 的迟到合成回调核对当前媒体并限制为有限时长。依赖版本固定，在独立构建副本应用受校验的修复，不修改 pub 缓存。

本地 EVENT 播放列表声明从零开始，初始化不再额外发起异步定位，续播和手动拖动保留。上一版无进度恢复不能检测进度持续前进的画面冻结，本批修正渲染与启动路径；真机复测点和自动化边界见 [原生修复记录](ios-progressive-rendering-2026-10-03.md)。

## 0.11.3 开播缓冲与站源选择

针对红果提前开播已出画面却卡在开头的反馈，EVENT HLS 开始播放前等待至少三个目标分片时长；完整短视频不受该门槛限制。渐进媒体连续 10 秒无进度时回退完整准备，原生等待状态也参与检测，手动暂停、后台和已播放结束不触发；普通媒体仍沿用 20 秒恢复间隔。

站源切换和记录筛选共用可搜索的网格弹窗，正常手机／平板布局直接展示十六站，大字体和键盘弹出时可滚动。切源取消旧搜索，迟到结果不覆盖新站目录。范围、自动化验证及真机复测点见 [修复记录](playback-startup-and-source-picker-2026-10-03.md)。

## 0.11.2 恢复与后台交接

有限恢复预算、恢复期间的互斥与迟到线路释放，以及播放意图、800 ms 自动 PiP 交接、后台挂起和完整准备后的恢复已移入独立控制器。兼容恢复会核对交接期间的最新意图，关闭 PiP 不再被旧的继续播放请求覆盖。页面提供原生播放效果和 UI 回调；系统事件适配、实际兼容视频准备、观看记录和预取调度仍保留在页面。范围与验证见 [协调整理记录](playback-coordination-2026-10-03.md)。

## 0.11.1 播放会话整理

将资源准备、前台接管、缓存有效期、清晰度与完整准备策略、资源释放及原生播放源交接收进独立会话控制器。播放轮次校验阻止迟到准备结果进入新的播放，原生设置串行执行并跳过过时请求，设置失败不会阻塞后续恢复。补齐备用资源被覆盖、移出保留范围及关闭后提交时的释放。页面继续负责控件、播放意图、恢复预算与生命周期／PiP 事件，本轮没有完成全部协调逻辑的抽取。详细范围和验证见 [会话整理记录](playback-session-2026-10-03.md)。

## 0.11.0 首段预取

3. **联网搜索**：黄果联网搜索仅覆盖 AI 子源；黄豆仍仅本地筛选，不能将本地结果标作联网成功。
4. **投屏保持前台**：Google Cast / DLNA 当前通过手机中转资源，界面提示保持果果前台。发现成功不代表所有编码与电视组合都能播放；自签环境下的本地网络/组播权限也需验证。
5. **投屏控制**：已实现独立会话、播放／暂停／结束及设备实际进度交接；关闭面板继续投屏，离开播放器结束会话。设备不报告进度时保留原位置；协议时刻精度、接收器定位能力及 iOS 真机交接仍需设备验证。投屏端选集、自动连播和断线重连为下一批。
6. **离线整理**：后台负责资源传输，媒体整理在回到应用后执行。不承诺 iOS 强制关闭应用后持续执行媒体处理。单个资源若不支持断点恢复，会重传该资源，已经完成的分片可保留。
7. **分片格式边界**：离线资源规划暂不支持含独立音轨的主清单和直播清单，并会明确报错。
8. **图像与推荐**：封面失败有回退样式；HEIC 封面解码仍需设备验证。当前展示站源目录与榜单，没有个性化推荐算法。
9. **Android**：保留工程和桥接构建入口，当前没有 Android 安装包或真机验证结论。

以上不是删减已确认的最终产品目标，而是说明当前开发版本可验收的范围。不得以此文档或一次目录请求成功代替完整产品验收。
