# 记录保存优化（2026-10-04）

版本 `0.12.1+28`。接续已合并的新季提醒，完成下一批记录保存优化。

## 保存行为

播放器仍按原有的进度间隔以及切集、兼容恢复和退出路径提交真实位置，没有新增延迟保存队列。本批在 AppStore 中比较位置、分集 ID／原始索引、时长以及剧集资料；这些内容都相同时不写盘、不通知历史列表，也不更新观看时间。向后拖动、未知时长变为实际时长、切换分集或资料变化仍保存。之前保存失败时，即便位置相同也重试。

历史条目按不可变 WatchRecord 实例缓存其 JSON 数据。改变的条目重新生成，删除的条目清理缓存；详情资料更新、备份合并与失败回退按实际实例重新生成，不把旧行留在保存结果中。完整记录文件仍会编码并原子替换，本批没有改成数据库或增量日志。

## 文件与迁移

应用支持目录 `records/` 中使用两个文件：

| 文件 | 内容 |
| --- | --- |
| `records.json` | 收藏、观看历史、新季提醒及基准／已读、分集已读 ID、最近搜索、分类选择、偏好与播放诊断 |
| `catalog-cache.json` | 目录条目、分类列表／分页、搜索结果、分集资料与刷新时间 |

记录与缓存各自保持调用顺序，先分离输入快照，再由独立队列在 isolate 中编码、写临时文件并 flush／rename。记录保存不会遍历缓存，也不等待正在写入的目录缓存。混合更新会立即将两份快照分别排队；每个文件独立提交，没有跨文件事务。首次安装只更新缓存时也会建立初始记录文件，重启后可读取缓存。下载清单继续使用原有单文件存储，路径与格式未变。

旧 `state.json` 继续可读。先写入记录时，重启从新文件读取最新观看位置，并从旧文件读取尚未迁移的缓存；先写入缓存时，旧文件仍提供记录。两个新文件都成功提交后才删除旧文件，清理失败不影响已保存结果。迁移按实际修改发生，不在启动时强制重写整份剧库；中途退出不会改用旧位置覆盖新记录。

新的记录文件一旦存在就成为记录的唯一来源。损坏时保留文件并报告读取失败，不退回旧观看位置。缓存 JSON、版本或条目损坏时丢弃缓存并提示联网重新加载，收藏、历史、偏好、分集已读和新季提醒仍可读取。分集已读 ID 属于用户状态，不随缓存丢弃。

## 失败与兼容

记录和缓存失败分别提示，缓存成功不会清除记录保存失败。混合更新中缓存失败不撤回已提交的记录；单独导入剧库时，缓存保存失败仍撤回本次导入。后续成功保存对应文件会清除相应提示，旧文件仅在两份替代数据都就绪后清理。

本地记录字段保持现有版本。记录导出仍为 `guoguo.records` v1／v2，包含新季提醒时用 v2；导入、时间合并和提醒已读行为保持兼容。普通 LocalStorage 的测试／自定义实现继续支持完整快照，生产启动使用分离文件实现。
