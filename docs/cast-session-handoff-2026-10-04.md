# 投屏会话与手机／电视交接（2026-10-04）

版本 `0.13.0+29`。接续记录保存优化，本批实现独立投屏会话和实际进度交接。

## 操作与归属

`CastSessionController` 由播放器持有，控制面板只展示会话和发现设备。收起面板继续投屏，可从播放器中央入口重新打开；结束按钮才交回手机，离开播放器则结束会话并释放中转服务器。设备搜索属于面板，关闭时取消监听；Google Cast 全局发现通过串行命令和活跃面板引用管理，旧面板的迟到初始化／搜索不会停止新面板的搜索。

选择设备时才读取手机实际位置、时长和播放状态。先保存位置并暂停手机，再连接接收器、启动媒体中转并加载。提前开播仍先完成兼容媒体准备；已下载的完整 MP4 可直接使用本地资源。投屏期间禁止本地拖动、上下滑切集、自动下一集、倍速／线路恢复和 PiP，迟到的手机播放事件会再次暂停，不改变电视播放意图。

## 位置与状态

| 阶段 | 行为 |
| --- | --- |
| 开始 | 使用选择电视时的真实手机位置及播放／暂停状态，等待接收器确认加载 |
| 控制 | 前台每两秒串行读取实际状态；播放／暂停命令和停止与状态读取互斥 |
| 结束 | 先读取最后实际状态，再确认电视停止、释放资源、定位手机并恢复相应意图 |
| 不支持进度 | 保留开始投屏时的手机位置，界面提示接收器不提供进度，不推算时间 |
| 读取暂时失败 | 保留最后确认的位置，不将未知值改为零；仍可重试结束 |
| 停止未确认 | 保留会话、中转和手机暂停状态，提供重试结束 |
| 返回后台 | 停止主动轮询；交接不会在后台启动手机，回到前台后再按最新意图播放 |

电视进度按原分集 ID 和原始索引保存，沿用现有记录文件与保存失败行为。正常停止读取实际位置后才发停止命令，避免接收器将停止后的零进度覆盖观看记录。返回位置限制在已知时长内，结束位置不自动开播。单次媒体加载、控制和结束有时间限制；连续点击结束复用同一操作。

Google Cast 校验设备身份、当前媒体 URL 和媒体会话 ID，拒绝旧媒体和加载后尚未收敛到请求位置的旧进度。确认本次加载后支持电视向后拖动，后续状态不会把它误判为旧进度。DLNA 只有匹配当前 TrackURI 的时间才用于交接；进度和时长支持协议返回的小数秒。明确换成其他媒体时不再对其播放、暂停或停止。

## 协议依据与失败

Google Cast 加载使用 `autoPlay` 和 `playPosition`，与 [Google 加载请求定义](https://developers.google.com/cast/docs/reference/ios/interface_g_c_k_media_load_request_data) 对应。锁定 `flutter_chrome_cast` 1.4.8：该版 iOS Dart `loadMedia` 没有等待原生调用，本批等待已核对的相同 MethodChannel 调用并额外检查接收器状态，使原生加载失败进入可处理的错误路径。开始位置按此版本原生契约传整秒，回读精度取决于 SDK 和接收器。

DLNA 按 [UPnP AVTransport:1](https://upnp.org/specs/av/UPnP-av-AVTransport-v1-Service.pdf) 使用 `GetPositionInfo`、`GetTransportInfo` 及 `REL_TIME` 定位。加载顺序为设置媒体、播放、定位、按原意图暂停。SOAP 必须有对应动作响应，HTTP 200 内的 SOAP Fault 仍按失败处理。非零位置定位失败会停止本次投屏并保留手机原进度，不假报已从原位置开始。

失败加载也可能已在电视端启动，因此恢复手机前同样先确认结束；停止失败则保留控制入口。关闭播放器使所有迟到结果失效，关闭中转与接收器资源，异步尝试停止电视，不回调已销毁页面。页面离开后的停止属于尽力清理，断网时无法保证电视收到命令。
