# 状态与页面更新边界

## 状态归属

- `AppStore`：装配各状态对象、离线状态、诊断样本、记录/缓存分区持久化及读写错误。不转发所有子状态通知。
- `PreferencesStore`：主题、网络偏好、预取、倍速、自动连播和提前开播。主题单独通过 `theme` 通知应用外壳，其他偏好不重建 `MaterialApp`。
- `CatalogStore`：目录、分类、搜索、详情、分集缓存与同系列查询。保留请求去重、取消、分页和缓存策略。
- `RecordStore`：收藏、观看历史、已读分集基准、新季提醒、备份与更新检查。通过注入的分集/同系列查询回调检查更新，不依赖目录界面的生命周期。
- `StorePersistence`：状态对象使用的最小持久化接口，保证业务操作继续走统一的分区写入和失败恢复路径。

`CatalogStore` 获取新资料后通过 `RecordStore.updateDrama` 更新已保存的剧集资料；获取分集后通过 `episodesUpdated` 建立已读基准并通知新增集数变化。可以重建的分集列表仍在目录缓存中，已读基准仍在记录文件中。

## 记录提交边界

记录修改与记录文件写入使用同一个操作队列。队列中的保存回调直接落盘，不再次入队；网络请求和缓存写入不占用记录队列。设置等触发的记录保存也在进入队列后取得快照，不能把尚未完成的记录事务带入其他写入。

备份导入先脱离输入的可变集合，再在队列中合并出候选数据；候选保存成功后才安装并通知。失败不修改当前记录，排队中的观看、收藏、提醒操作随后正常执行。普通观看位置仍保留失败后重试的行为。记录 Map 与已读集合对外只读，`restore` 仅用于开始记录操作前的初始化。

`updateDrama` 和 `episodesUpdated` 是异步记录操作，目录层等待它们完成后单独保存缓存，避免嵌套队列和重复记录写入。关闭后不接受新记录操作，关闭前已接受的保存会完成但不再发送页面通知。

剧集资料通过 `Drama.hasSameMetadata` 比较实际字段与标签内容，不为变化检测生成 JSON。资料没有改变时保留原收藏和历史对象，跳过记录写入与通知；已读分集 ID 集合没有改变时也跳过保存。存在记录保存错误时仍允许相同内容重试，不能让去重阻止错误恢复。

## 观看集号

`WatchRecord.episodeIndex` 是原始队列位置，`episodeNumber` 是可选的站源真实集号，播放器按当前 `Episode.number` 保存后者。首页与历史共用 `RecordStore.episodeNumberFor`：按分集 ID 查找缓存中的真实集号，缓存缺失时使用记录保存的集号；两者都未知时显示“上次观看”，不从队列位置推算。

更新剧集资料通过 `WatchRecord.withDrama` 保留分集身份、集号、位置、时长和观看时间。追剧页顶部续播与下方历史使用同一份来源筛选后的记录，不重复获取与排序全部历史。

## 播完与续播

`WatchRecord.episodeCompleted` 仅保存当前记录分集的确认播完状态。手机播放器的有效结束事件和 AirPlay 的原生 `ended` 状态可以标记播完；未完成的渐进媒体结束、投屏停止或位置达到时长不能单独证明播完。换集、重播或向前拖动进度会清除当前分集的完成状态；退出、后台保存和播放交接继续保留它。该字段跟随记录持久化、备份和资料更新，缺失时按未播完处理。

`WatchResume` 按分集 ID 在完整目录中计算续播目标。播完且存在后续分集时进入下一集；连载最新集显示“等待更新”；只有站源明确完结且播完目录最后一集才显示“已看完”。缓存或分集身份缺失时只显示“本集已看完”。无需新增持久化状态，目录更新后自动重新计算。等待更新和已看完仍保留历史，但不占用续播卡片。

详情页与续播卡片共用目标计算，已看完的剧集提供从头重新观看。离线续播按下载记录的原始位置选择相邻分集，缺集时重看当前集，不把下载队列末尾当作全剧末尾。

续播、本地自动连播和 AirPlay 自动队列共用 `nextAdjacentEpisodeIndex`。完整目录按列表顺序前进；离线下载队列只有原始位置相邻才自动前进，真实集号不参与相邻判断。缺集时保留本集完成记录并停止自动连播，本地播放器提示缺集且提供按真实集号选择后续下载的按钮。AirPlay 不预先加入跨越缺集的视频，原生界面显示提示并把“下一集”改为具体的播放集号，只有用户主动选择才加入并切换。

## 订阅原则

- 首页外壳不监听所有业务变化。通知提示、目录和个人记录分别订阅各自状态，标签页继续通过 `IndexedStack` 保留。
- `RecordStore.progress` 只通知观看位置与播完状态变化；继续观看和历史条目订阅它，目录网格的收藏图标不订阅它。
- 目录页的搜索/列表监听 `CatalogStore`，每张卡片的收藏状态监听 `RecordStore`。
- 播放器仅订阅 `PreferencesStore` 的偏好更新；目录加载、收藏和观看位置不再触发播放器偏好处理。
- 详情和同系列区域显式订阅其确实使用的多个状态，不依赖 `AppStore` 的全局转发。
- 持久化错误及恢复通过 `AppStore` 通知；正常记录写入不发送全局通知。

## 下载恢复边界

本地记录与目录缓存载入后就展示首页。`AppStartup` 分别协调站源初始化、下载恢复和网络状态检查；站源与网络失败提供各自的重试入口，不替换首页或清空当前标签。只有本地记录读取失败仍使用启动错误页，原文件保持不变。播放临时目录清理仍在任何播放会话创建前完成，清理失败不阻止读取记录。

站源核心只允许一个初始化任务；普通请求与封面共用 `NativeProviderClient.shared`，等待初始化及协议验证完成后才发送。初始化失败阻止后续请求，显式重试成功后恢复；不会自动为每个请求重新初始化。下载先读取本地清单、修正容器路径并展示已有视频，再等待站源就绪并恢复任务。未就绪期间阻止入队、暂停、重试、删除和下载网络规则修改，避免与恢复、孤儿清理竞争。

下载初始化的并发调用共用一个任务，失败后的重试保留已经读入的清单，不重复读盘覆盖当前条目。插件的单订阅更新流在驱动层共享，恢复重试只重新订阅业务监听器。网络监听先于初始检查安装，较新的监听事件优先于迟到的检查结果；检查失败保留监听器，监听中断后可重新订阅。退出后释放监听和状态对象，迟到的初始化结果不再启动后续步骤、写入目录缓存或通知页面。

启动恢复按下载条目处理。原生入队返回 false 或抛异常时，该条目进入可重试的失败状态并保存清单，其他条目继续恢复；签名刷新仍复用原有 retry 路径，不删除已保存分片，也不恢复用户主动暂停或已完成的条目。

下载清单的保存错误独立于普通读取错误：reload 成功不能清除尚未恢复的清单保存错误，后续成功保存才清除并通知。

## 播放器边界

`player_transport.dart` 和 `player_sheets.dart` 负责进度/倍速控件及选集、相关剧集、更多操作的展示。它们通过回调报告用户操作，不持有媒体资源。

`PlaybackProgressController` 保存当前分集身份、播完状态、记录快照和统一的十秒周期提交间隔；切集、后台、退出、重播和投屏交接仍立即提交。页面提供确认播完事件和当前播放设备的位置，控制器在提交时固定分集 ID、原始位置和真实集号，再交给 `RecordStore` 的既有写入队列。

AirPlay 返回手机期间，观看记录继续采用原生队列的分集和位置，直到手机恢复完成；旧手机源先解除当前播放身份。准备或恢复定位期间进入后台，以及恢复失败后退出，都不能把旧手机位置写到当前 AirPlay 分集。

`PlaybackFailure` 将已知连接失败、离线缺文件、取消和 AirPlay 占用转换为固定提示，未知异常使用通用文案。离线缺文件只接受主动重新检查或选集；取消、存储不足及组件未就绪不执行自动恢复。连接失败沿用有限恢复预算，耗尽后保留网络提示。诊断仍只记录既有结构化字段，不保存异常文本或媒体地址。

`PlayerNotice` 共用缺集、播放失败及 AirPlay 提示的布局。远端占用时隐藏本地重试，使用系统设备选择入口；因路由拒绝的播放在切回 iPhone 后恢复。AirPlay 返回失败提供专用重试，设备选择和返回期间阻止重复操作，并保留原有进度与播放意图。

`PlayerPage` 继续协调既有播放、恢复、生命周期和独立投屏会话；本轮没有合并 AirPlay 与手机播放器，也没有删除设备兼容、失败回退和换集资源保留逻辑。

## 回归测试

- `test/record_transactions_test.dart`：候选提交、并发修改、失败重试、只读集合与真实文件重启恢复。
- `test/scoped_store_test.dart`：状态通知隔离、持久化错误恢复、观看位置与收藏的局部更新、主题专用通知。
- `test/player_sheets_test.dart`：选集/VIP 展示、禁用操作、自动连播和清晰度回调。
- `test/record_maintenance_test.dart`：无变化资料与已读集合跳过写入、失败后的相同内容重试、集号保存与缓存缺失时的恢复。
- `test/app_startup_test.dart`：先展示本地内容与主题、分组件失败与重试、网络检查与监听竞态、初始化及目录响应期间退出。
- `test/provider_initialization_test.dart`：初始化与协议验证的请求门控、并发初始化去重、失败后重试及异常信息处理。
- `test/download_initialization_test.dart`：清单先呈现、恢复期间修改保护、失败重试、损坏清单保留文件、未就绪的网络规则与初始化期间释放。
- `test/watch_resume_test.dart`：按 ID 计算下一集、完结/连载/未知状态与目录更新后的续播恢复。
- `test/episode_queue_test.dart`、`test/offline_episode_gap_test.dart`：原始位置相邻判断、缺集时本地/PiP/AirPlay 停止自动连播、连续下载与手动跳集、重播/回退后清除提示。
- `test/playback_progress_test.dart`、`test/player_cast_handoff_test.dart`：进度提交节流、记录快照身份、写入失败后重试，以及 AirPlay 返回期间准备/定位阻塞和失败时的进度归属。
- `test/playback_failure_test.dart`、`test/player_error_actions_test.dart`：固定错误提示、有限网络恢复、离线重新检查和选集、取消诊断及重复重试；AirPlay 设备选择/返回失败的恢复操作由交接测试覆盖。
- `test/continue_and_range_test.dart`：非连续原始集号展示、追剧续播来源筛选、播完状态展示、离线缺集与下载范围。
- 原有分区存储、备份、更新提醒、请求取消、播放器交接和 PiP 测试继续保留。

CI 的 iOS 编译及模拟测试不等于 AirPlay 接收器或 PiP 真机验收。
