## 已实施

| 项目 | 最终行为与边界 |
| --- | --- |
| F2 首次下载提交与操作交错 | 暂停、重试、删除先停止该条目的后续提交，等待在途提交返回，再处理原生队列。其他分集保持独立。Store 关闭时，未提交完的批次停止并保留可恢复记录；已提交完的原生下载继续运行。取消被拒绝时保留文件、任务身份和可重试状态。 |
| F4 无效的已完成文件 | 显式刷新和离线取用共同校验普通文件且大小大于零。缺失/空文件降为可重试，保存失败继续显示清单错误。进度刷新不扫描文件。 |
| F5 网络策略 | 首次网络快照、连接变化、剧库预取和下一集预缓冲复用同一策略。未允许蜂窝时，Wi-Fi 与 mobile 混合列表不触发预取；空列表和 none 均不允许预取。保留已授权蜂窝策略及前后台/PiP 限制。 |
| F1 红果真实分页 | 不可变游标同时保存官网页号、是否还有官网结果、名称检索待重试与原有分季状态。每次续页至多读取一个官网页，全部分支合计至多 4 个远程请求/10 秒；保留 200 个结果、最多 200 页、32 次补季请求及游标容量/有效期限制。失败分支不消耗官网页或补季进度，可在下一次继续加载；新页面发现的季数进入原有补季流程。 |
| F3 目录排队与缓存 | 红果、黄果、黄豆各自协调目录请求；等待响应 context 超时/取消。共享快照与缓存写入单独串行，网络请求不持有共享缓存门。黄果只提交自己的游标副本，红果取消后恢复未提交的 feed 位置，其他来源写缓存时使用已提交的红果状态。磁盘写入本身仍依赖操作系统 IO 完成。 |
| R1 启动记录恢复 | 本地读取失败页可进入恢复页，导出原文件、预览 v2 备份恢复或确认后重新建立记录。覆盖前在记录目录 `recovery/records-*` 下保存并 flush 原文件副本，然后复用原子写入；保留失败会阻止覆盖，写入失败仍保留原件与副本。目录缓存和下载不参与恢复写入。偏好设置会重新建立，确认页会说明。 |
| R2 启动过渡 | 跟随系统暗色；等待、报错、重试和恢复入口置于 SafeArea 与可滚动布局，覆盖短横屏及大字号。 |
| R3 保存重试 | 主界面告警提供独立“重试保存”，复用记录队列与当前内存状态。进行中不重复提交；失败仍保留提示，不再次切换收藏/偏好或请求网络。 |
| 野果入口 | 复用现有同线路静态 import 遍历，允许从当前客户端模块发现 API base，再与独立配置模块配对。仅接受已识别野果主机的静态 HTTPS `/api.php` 地址，且该函数必须被 `baseURL` 引用；继续保留显式 API 配置与旧 Nuxt 字段入口。 |
| 小范围优化与拆分 | 下载占用清理在 IO 后一次构造当前 ID Set，替代逐 key 扫描全部条目。Go 聚合目录处理从 `MobileClient.Call` 提取为独立域实现。记录备份校验、选择文件入口由设置页和恢复页共用。探针通过返回退出码再退出，错误分支也执行资源与临时目录清理。 |

恢复副本属于用户记录，不自动删除；系统分享面板取消不影响本机副本。恢复成功后的首次正常启动仍按原有流程读取缓存和恢复下载，损坏缓存继续降级处理。

## 可复现的备份解析量测

脚本：[scripts/benchmark_record_backup.dart](../scripts/benchmark_record_backup.dart)。Linux 主机，Flutter 3.47.4 附带 Dart 3.13.3，AOT 编译后每组运行三次。合成输入只包含合法当前格式的收藏记录，不涉及真实用户数据。

```sh
dart compile exe scripts/benchmark_record_backup.dart -o /tmp/guoguo-backup-benchmark
/tmp/guoguo-backup-benchmark
```

| 样本 | 同步解析耗时 | 当前路径耗时 | 同步事件循环最大间隔 | 当前路径最大间隔 |
| --- | --- | --- | --- | --- |
| 80 条，52,707 字节 | 1.27–2.27 ms | 1.32–1.87 ms | 2.21–3.27 ms | 2.34–2.88 ms |
| 25,000 条，16,577,867 字节 | 431–481 ms | 477–526 ms | 432–482 ms | 26–35 ms |

当前路径对不超过 64 KiB 的小备份直接校验；大备份的 UTF-8、JSON 与记录模型解析移到 isolate。20 MiB 上限和 v2 格式校验保持一致。后台解析的收益是减少主 isolate 的连续阻塞，并非缩短总处理时间；大对象传递仍有开销，导入事务的合并、安装与导出编码没有据此宣称消除停顿。设备速度、内存与热状态会影响结果。

## 验证记录

- 先加入受控用例，在旧实现中实际复现暂停/删除迟到提交、Store 关闭后继续提交、空文件仍可播放等 8 个失败；修复后相应用例通过。
- 下载回归覆盖在途提交暂停/删除/关闭、取消拒绝、提交拒绝、跨分集独立性、文件缺失/截空和清单写失败；保留既有完成分片、签名地址刷新、整理失败与清单错误分离测试。
- 网络与播放器覆盖 Wi-Fi/mobile 混合、none、空列表、VPN 组合及预缓冲中网络撤销；原有 PiP、生命周期、资源回收测试继续运行。
- Go 覆盖官网去重续页/令牌重放、官网和名称分支恢复、新季发现、取消；目录覆盖 100 ms 排队超时、取消、跨来源并发、相反完成顺序、未提交快照隔离、写失败保留内容及取消回滚。全量 Go、针对这些路径的 race 检查和 vet 通过。
- 恢复覆盖原始损坏字节、备份/空记录的完整载入、写入失败、保留失败、串行写入、无效备份、用户取消、确认恢复和恢复错误；启动页覆盖 640×320、系统暗色与 2 倍字号。
- 红果真实文本探针搜索“大佬”：首屏 20 个唯一 ID，官网续页后 32 个，warning 为空。结果数量随上游变化。
- 野果真实文本探针：目录 20 部，warning 为空，样本详情/分集 7 集。只验证所选文本样本，未读取视频。
- Flutter 全量 906 项通过、15 项按环境跳过；另指定主机 FFmpeg 补跑媒体、HTTP relay、完整 CENC 准备/解码及新增下载交错用例，18 项通过。共享备份选择器最终调整后，设置与恢复页面 16 项通过。
- `flutter analyze`、Dart 格式检查、发布元数据校验、29 项 Python 工具测试及 actionlint 通过。失败探针实际以退出码 1 返回，隔离的临时目录内残留为零。

完整远端 CI 与 iOS 构建结果由对应 PR 检查记录。这里的主机测试不表示设备长时间连播、后台下载、真实 PiP、AirPlay、投屏接收器或 VoiceOver 已重新验收。

## 本批未据此扩大改动的项目

- 观果：另查五个目录 ID，详情均为 HTTP 成功、业务 code 200，但 title/data 为空且集数为零；`queryAll` true/false/不传均未恢复。当前明确报错与空响应回归继续保留。需要一个当前可播放 ID 与有效请求契约，不能用空数据伪造详情。
- 帝果连通性、黄果部分线路回退、皮果/爽果验证限制：维持 [原巡检](source-check-2026-10-24.json) 的环境边界，本批没有将它们归为已修复，也未删除适配器。
- 下载事件增量归并、隐藏页面派生列表、启动清理时序、缓存工作集上限与进一步播放器拆分：仍需相应规模/设备数据和独立行为回归。当前优先消除了已确认竞态、错误状态与有量测依据的备份解析阻塞；继续复用现有存储、播放器与状态分区。
