# guoapp 融合实施记录

## 决策与范围

2026-09-24：以 guoguo-mobile 保持应用身份、现有记录和 iOS 交付路径，逐模块吸收同级 guoapp 的优势。保留暖白／墨绿与深色主题、手机观看流程；为不同平台隔离媒体和后台任务能力，避免一次替换所有原生依赖。

第一批（0.6.0+14）已合并；第二批（0.7.0+15）验证提前开播，不代表整个多平台重构完成。参考 guoapp 的播放恢复、预加载时机、详情固定操作与选集定位设计，在当前数据和平台接口上实现，不覆盖参考项目源码。

## 第一批实现

### 播放恢复

Go 移动接口解析时去重可用线路，返回会话及线路数量；`fallback` 复用已有解析结果打开下一条线路。自动模式按清晰度排序，手选清晰度仅使用同档线路。会话释放同时删除线路和代理；最多保留八个会话，两分钟前解析的备用线路要求重新解析。

Dart 将恢复预算、卡顿判断和预加载触发条件提取为独立策略。每次选集／手动重试重置预算，最多三次自动恢复，备用线路不可用时仅重新解析一次。切线保留观看位置与倍速；过期异步结果释放会话，不重新启动已经退出的播放器。

卡顿检测仅统计前台、实际播放、非加载、非菜单和非拖动状态。预加载等待当前集缓冲充足并进入后半段或最后 45 秒，继续遵守 Wi-Fi 偏好；失败间隔至少 30 秒。取消后台预加载，PiP 仍保持原有连续播放路径。远程地址准备结果保留两分钟，本地完整文件可继续复用。

### 界面与交互

- 详情底部固定播放／继续观看与下载，不随简介和选集滚出屏幕。
- 手机共用一条滚动区域，宽屏分栏；历史改变后更新续播按钮。
- 选集保持每页 30 集、原始集数与输入跳集，增加定位当前和选中语义。用户浏览其他范围时，进度刷新不抢回当前页。
- 播放加载和出错时保持可退出、可选集；正常观看沿用轻点显隐和手势。
- 自动连播开关与常用倍速保存在本机，临时长按加速不改偏好。已有版本缺少这些字段时仍默认自动连播、1 倍速。

## 第二批：提前开播实验（0.7.0+15）

保留现有 BetterPlayer／AVPlayer 和链接的 FFmpeg，仅增加可撤回的准备路径。设置中的“播放诊断”提供默认关闭的实验开关；只对从头播放的加密 MP4 启用。已有本地文件、明文视频及 HLS 沿用原路径，预加载也不启用实验。

FFmpeg 解密并复制音视频为 fMP4 EVENT HLS，先等待初始化段、首个完整分片及清单，再通过带随机令牌的 IPv4 loopback 地址交给播放器。[FFmpeg HLS 文档](https://ffmpeg.org/ffmpeg-formats.html#hls-2)说明了 EVENT 清单和 `temp_file` 原子替换行为。服务只开放本会话清单和完整分片，支持播放器 GET／HEAD／单范围读取，拒绝临时文件、链接和任意路径；上游请求头不会传给 loopback 播放器。

每次准备独立持有原生会话、临时目录和 HTTP 服务。首段超时 45 秒回退完整准备；实验输出每 500 毫秒检查 128 MiB 空间预算及 5 分钟处理时限，可能短暂超过预算，不能视为操作系统磁盘配额。超过限制或生产失败时停止实验并回退。取消只作用于自身 FFmpeg 会话，确认写入停止后才删除文件；临时内容不进入下载索引。

界面显示“已准备”时长，拖动范围限于播放器当前可用区间；已有观看位置的续播直接使用完整准备。播放异常、生成中提前结束、画中画、投屏和 AirPlay 入口会切换完整准备；后台停止实验，返回前台时恢复原位置和播放／暂停意图。AirPlay 在准备完成后再显示原生设备选择入口。当前实验仍在生成时不竞争下一集预加载。

诊断新增准备方式及兼容回退标记；旧记录可读取。实验仅验证技术路径，不承诺“秒开”或真机性能提升。Linux 合成媒体与播放器模拟不覆盖 iOS 的实际起播策略、PiP、AirPlay、编码兼容和耗电，默认开关应保持关闭直至设备验收。

### 第二批验证

本地全量 Flutter 回归 109 项通过，3 项可选预览按环境跳过；随后补充切集过程中取消尚未就绪实验任务的回归。覆盖令牌／路径限制、分片范围读取、取消时序、超时回退、生产错误、后台恢复、暂停意图及旧偏好兼容。发布工具 7 项测试及版本校验通过。

使用 `GUOGUO_FFMPEG=ffmpeg` 运行 8 秒、180×320、10 fps 的合成 H.264 CENC 视频，通过 `-re` 控制输入节奏：loopback 清单和首段在 1,471 ms 可用，生产完成在 7,281 ms；开始和完整解码的帧哈希分别与原视频解密结果相同。命令和断言见 `test/progressive_ffmpeg_test.dart`。该数据不包含真实站源、设备渲染或音频，也不是首帧时间与完整准备路径的性能对照。

### 0.7.1 真机反馈修复

用户反馈实验可播放但时长显示 0、进度条停在起点。查阅锁定的 BetterPlayer 1.4.1 源码：iOS 允许不定时长 HLS 初始化并将时长转换为 0，Dart 只在 initialized 事件保存时长，seek 又被限制到该值。此前播放器模拟固定返回 30 秒，未覆盖这条真实边界。

修复由本会话生成的原子清单提供持续更新的时间轴，只累计已完整发布分片的 EXTINF 时长，不使用墙钟估算。播放器保持原生位置更新，同时用真实可用范围更新控件和 seek 边界；最终清单校验后才认定完整。监听随切集、重试和退出解除。未完成时历史只记录真实位置，整集时长记为未知（旧格式已支持 0），首页显示已观看时间。

本地验证：`flutter analyze --no-pub` 无问题；全量 `GUOGUO_FFMPEG=ffmpeg flutter test --no-pub --concurrency=1` 共 118 项通过、3 项可选预览跳过，包含合成 CENC 完整解码与时间轴验证；格式检查、发布版本校验和 7 项发布工具测试通过。

该实验按媒体格式启用，目前主要对红果加密 MP4 生效；直接播放的 HLS 没有整集解密等待，不走实验路径。仍需用户在 iOS 上复测时间推进、拖动、暂停、切集和连续播放。

## 后续顺序与验收条件

1. 播放内核对照：固定设备、媒体及网络，比较首帧、随机跳集、拖动、内存和耗电；验证 iOS PiP、AirPlay 后决定是否引入 media_kit 或流式整理。第二批增加默认关闭的流式准备实验；设备性能和系统功能验收后再决定是否推广，默认路径仍完整准备。
2. 共享数据模型和迁移：明确站源／剧集／分集身份，扩展追剧状态和数据存储；旧历史、收藏与下载索引可恢复后再切换。
3. Android TV 焦点、遥控和独立布局；站源能力分组、多剧下载与增量补集。分别验收手机、平板及电视。
4. 局域网同步、推送播放、本地合并与导出。通用投屏和应用间互联保留独立协议实现。

当前没有引入更多站源、多用户、数据库、Windows 画质增强或 Android 前台下载服务；这些不作为本轮完成项。
