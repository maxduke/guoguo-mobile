# 黄果默认线路发现恢复

## 复现与原因

v0.20.14 的黄果新取流接口在指定有效内容线路时可以读取媒体，但干净客户端仍会失败。默认线路发现依赖 `huangguoai.ai` 和 `huangguoai.pages.dev`，两者在本机均发生 TLS 连接失败。此前指定内容线路的主机验证跳过了这一步，不能证明默认入口已经恢复。

未设置线路、没有线路缓存的 `cmd/probe -source huangguo -query 都市 -media` 实际失败，日志为 `/tmp/guoguo-yellow-default-current.log`。对照 [官方入口](https://huangguoai.ai/) 的“黄果短剧最新地址”链接，确认 `https://hgai15.com/` 是另一个官方线路发布入口；该站在同一主机网络可读取，并使用既有 `data-url` 格式发布内容线路。

## 修复

主入口没有有效线路时，先读取上述独立官方入口；只有它也失败或没有有效线路，才继续已有的 Pages 发布页/脚本路径。仍使用统一八秒发现总期限，每个备用页面最多三秒。入口仅负责发现线路，不被当作播放来源；没有把临时内容域名写死到应用。

读取继续隔离账号 Cookie 和 Authorization、拒绝重定向，并经过现有公网 DNS/TLS 校验。手动固定线路与已有有效线路不被覆盖；取消后的迟到页面不能安装线路或扩展已知来源集合。原有分集身份、CDN 请求头与媒体代理逻辑保持原流程。

## 验证

修复后的原版 `cmd/probe -source huangguo -query 都市 -decode` 使用临时空数据目录、无预设线路，不再修改测试偏好文件：搜索 24 条，作品 `huangguoai:2046` 详情 15 集，首集 HLS 媒体 HTTP 206/1024 字节，完整媒体准备与 FFmpeg 全集解码通过。日志为 `/tmp/guoguo-yellow-default-fixed.log`。

新增移动 API 回归从无线路状态串联搜索、详情、取流和初始播放列表，断言主入口失败后只读取一次备用入口，并保留实际线路 Referer/CDN 凭证。另有取消迟到结果、已知来源隔离、发布页后备及重定向拒绝覆盖。

Go 全量 826 个测试/子测试通过，零失败；8 项既有可选联网巡检未启用。相关黄果/媒体凭证竞态检查、`go vet ./...`、Go 格式与差异检查通过。日志分别为 `/tmp/guoguo-yellow-entry-all.jsonl` 与 `/tmp/guoguo-yellow-entry-race.log`。

主机默认流程成功并不等于用户设备已经验收。不同网络、手动固定的失效线路及后续媒体/CDN 失败，仍需结合具体错误判断；不以此宣称所有黄果作品或所有网络均已恢复。
