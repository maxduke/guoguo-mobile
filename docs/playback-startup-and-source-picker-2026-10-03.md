# 开播缓冲与站源选择（0.11.3+25）

PR #8 已合并到 main（`7667f6d`），原分支与工作区已清理。本次优先处理用户反馈：开启提前开播后红果已经出现画面，但卡在开头；十六站横向选择需要滑动太久。

## 提前开播

原实现只要 init 文件和一个已发布分片存在就交给播放器，典型可用范围仅两秒。[RFC 8216 §6.3.3](https://www.rfc-editor.org/rfc/rfc8216.html#section-6.3.3) 建议未结束播放列表的客户端至少保留三个目标分片时长，过于靠近列表末尾可能导致卡顿。修复据此按实际 `EXT-X-TARGETDURATION` 等待启动缓冲，不假定所有分片均为两秒。默认两秒分片会等待至少六秒的已发布内容，初次开播会多等几秒；有 ENDLIST 的完整短视频可以直接开始。缺失、重复或无效的目标时长不能被当成可播放输出，沿用超时后的完整准备回退。

原健康检测只观察 `isPlaying`，会遗漏用户仍希望播放、但原生播放器已经进入等待的状态。渐进媒体改为同时观察观看意图，连续十秒位置没有变化即取消渐进任务并走完整准备，保留当前位置、倍速和最新意图。普通媒体仍为二十秒。前台原生暂停也更新观看意图；设置源过程与无 PiP 的后台暂停不覆盖它。手动暂停、拖动、菜单、后台和播放结束均不被当作卡顿。

没有取得反馈设备的原生日志，启动缓冲不足是根据代码及 HLS 行为确定的可复现边界；本次修复及回退覆盖该边界，设备上的具体表现仍需安装后复测。

## 站源入口

`SourceSelector` 提供固定入口，点击当前站源后打开网格弹窗。手机正常字号三列，平板四列，十六站均可直接点选；可按中文标签或站源名称搜索。收藏／历史及下载保留“全部站源”，与关闭弹窗区分，选择当前站源不会重复加载。

大字体改为两列，弹窗内容可滚动，键盘弹出后仍能搜索和选择。切换剧库站源时立即取消旧在线搜索、清空查询并加载新站目录，旧源的迟到结果不覆盖当前列表。站源身份、分类和目录缓存沿用现有逻辑。
