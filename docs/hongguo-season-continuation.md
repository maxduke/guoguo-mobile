# 红果分季续搜

## 行为与取舍

0.18.0+39 适配 [guoapp 0.2.120+2127](https://github.com/maxduke/guoapp/tree/8b98b4731dad652767310397ee8ac03f9bc57a88) 的分批补季思路。首屏只合并名称检索及官网综合搜索，保留渐进显示；用户点击“加载更多”后查找其余季。原有直接核心搜索仍保持完整补季契约。

优先查询已知最高季之前的缺项，再尝试后续季。沿用标题规范化、同名同单位及已验证剧集元数据匹配；中文与数字季号都尝试。“季”和“部”隔离，同名不同 ID 保留。明确指定某季的搜索不自动扩大范围。没有结果的一批不提前结束仍有缺项的查找；后续季在连续两季的两种写法都没有结果后停止探测，不承诺站源绝无更高季。

上游的按搜索词共享可变游标未直接引入。移动核心保存不可变分页快照，以随机令牌绑定原查询及下一页；各拥有者只修改自己取出的副本，取消不改变其他请求。重放同一令牌从同一位置开始，不消耗全局游标。共享的首屏缓存与原有完整补季缓存分别存放。网络失败不记为已尝试，成功批次保留，可继续查找。

## 预算与缓存

- 每次续搜最多四次名称查询、十秒；一条续搜链最多三十二次查询、二百条结果。
- 最多保留六十四份快照，每份剧集元数据序列化不超过 256 KiB，令牌二十分钟后失效；到达保留数量时淘汰最早过期的快照。关闭核心释放快照。
- `hasMore` 只表示还存在可执行的季数查询；官网结果数量估计大于当前结果，不被当作可用分页。
- 未完成、已知缺季或预算耗尽保持 `limited`，不能把“本页已结束”当成完整查找。到达预算后提供完整剧名搜索提示。
- 令牌只在当前页面及核心内存使用，不写入搜索磁盘缓存。保存的未完成红果搜索重新联网获得首屏和令牌；离线资料保留。过期或不匹配的续搜保留已展示结果，重试重新搜索。

同系列及提醒沿用独立请求 ID、最多三页、二十秒与二百条展示上限。有有效令牌时可继续读取标为未完成的页；达到预算、警告、缺失季或结果限制时不建立首次提醒基准。手动刷新仍受核心首屏五分钟缓存及上游时效影响。

## 验证边界

合成回归通过移动 JSON 接口覆盖三十四季补齐、首屏不执行补季、四查询分页、空批次后的缺项、失败查询重试、相同令牌重放、并发取消、查询/页码隔离、过期及存储/查询上限。Flutter 回归覆盖令牌传递、过期后保留结果和重新搜索、磁盘缓存不含令牌、三页预算及完整性与提醒基准。

2026-10-10 主机文本抽查：“谁说没灵根不能修仙的”首屏约 2.05 秒返回二十一条，第二页增至四十个不同 ID，第三/四页保留四十条后结束续搜。最终仍标为未完整，未将官网未开放分页的结果估计当作完整系列。没有请求图片或媒体；这是当次站源样本。

主机文本探测可在 `native/core` 执行 `go run ./cmd/probe -source hongguo -query 谁说没灵根不能修仙的 -pages 10`，不读取图片或媒体。当前提交的 CI、iOS 构建及设备检查分别核对；编译或合成回归不代替真实站源持续可用率和设备体验。
