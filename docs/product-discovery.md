# 果果移动端：需求访谈

## 已确认

- 使用 Flutter，支持 iOS 和 Android。
- 首版同时适配 iPhone、Android 手机、iPad 与 Android 平板；平板提供多列海报、分栏详情等专门布局，不以简单放大手机界面作为验收标准。具体断点与横竖屏布局待设计。
- 运行边界为独立应用：手机直接获取内容、播放和下载，不依赖电脑、自建服务器或项目统一托管的业务后端。站源仍需要网络访问。
- 参考项目：https://github.com/maxduke/guoguo-video。
- 界面美观、交互体验良好是明确目标；具体体验验收标准待讨论。
- 视觉风格强调干净、舒适及海报与内容，支持浅色、深色和跟随系统，默认跟随系统。浅色采用暖白与墨绿，深色采用深灰与柔和绿色；播放器采用深色背景。
- 首版以找剧、追剧为主：首页展示继续观看、推荐和分类，用户选中一部短剧后连续观看，支持选集。推荐内容的来源与排序规则待确认。
- 首版必须覆盖红果、黄果、黄豆三个站源；各站源在手机端的直连接入与播放兼容性待验证。
- 剧库按站源分别浏览：先选择红果、黄果或黄豆，再浏览对应剧库。跨站作品合并不纳入首版。
- 首版支持侧载、自签安装即可，应用商店上架不作为首版交付要求。具体签名与安装工具待交付阶段确认；此选择不代表已确定使用人数。
- 首版提供完整下载管理：分集与整剧下载、进度展示、取消、删除、离线观看、暂停恢复、失败重试、批量管理和存储空间管理。
- 断网时允许浏览此前缓存的剧库列表、封面与详情，并明确显示离线状态；已下载的视频可播放，未下载的视频提示联网后播放。仅承诺访问已有缓存，不保证未加载内容在离线时可用。
- 后台下载采用尽力继续策略：切换应用或锁屏后尽量继续；被系统中断时保留任务，重新打开应用后自动恢复。不承诺应用被主动关闭后持续下载，具体平台实现仍需验证。
- 下载与下一集预缓冲默认仅限 Wi-Fi；切换到移动网络时暂停下载并停止下一集预缓冲，在线播放仍可使用移动数据。设置中分别提供允许移动数据下载、允许移动数据预缓冲的开关。任务恢复仍须遵守当前网络偏好。
- 追剧采用“收藏＋观看历史”：用户收藏感兴趣的短剧，应用自动记录播放进度并提供续播；首版不引入“想看 / 在看 / 已看”状态分类。
- 收藏、观看历史和下载任务跨三个站源统一汇总，每条标注站源并支持按站源筛选；切换剧库站源不改变这些个人内容的可见范围。
- 主导航采用“剧库 / 追剧 / 下载”三个底部入口，设置从顶部图标进入；默认打开剧库并记住上次站源。
- 剧库提供站源切换、搜索、分类、榜单和推荐；追剧提供继续观看、收藏和观看历史；下载提供下载中、已完成、批量操作和空间管理；设置包含外观、播放偏好和备份。
- 搜索限定当前站源：输入时筛选已缓存剧库，点击搜索或按回车后联网补充结果；各站源的联网搜索能力需分别验证，不能将本地筛选结果冒充联网结果。
- 收藏与观看历史保存在当前设备，支持手动导出、导入备份，以便换机迁移，无需账号。备份范围不包含已下载的视频；导入冲突处理规则待确认。
- 播放器支持上下滑动切换当前短剧的分集：上滑下一集、下滑上一集；保留选集面板，播放结束自动进入下一集。
- 首版必须支持画中画（PiP）与投屏。投屏接收设备、协议、播放资源兼容性，以及画中画的平台行为仍需确认与验证。
- 投屏期望覆盖三类设备：Apple TV / AirPlay 电视、Chromecast / Google TV、国内智能电视或盒子（包括电视自带接收端或乐播等）。用户表达为“最好支持”全部三类；此处记录覆盖目标，不代表任意手机与接收设备组合均已承诺兼容。具体设备、协议与真机验证范围待确定。
- 首版投屏仅支持在线短剧，不包含手机已下载视频的本地投屏。

## 已确认的播放器基础方案

首版包含点击暂停/继续、进度条跳转、倍速选择、长按临时 2 倍速、横屏、手势锁定、站源可用清晰度切换及下一集预缓冲，以及前述画中画与在线投屏。首版不做弹幕。
