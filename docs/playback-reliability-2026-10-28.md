# 播放初始化、取流取消与 Android 排队修复

落实 [v0.20.5 后审查](app-review-2026-10-28.md)中的三条可靠性路径。本批不增加产品功能，不调整推荐页、目录容量、账号或同步。

## 初始化等待与迟到事件

`PlaybackSessionController.installSource` 为获准安全退休原生实例的安装设置 30 秒期限；切集或关闭也会立即中断该安装。普通完成和已返回的失败继续复用已有播放器。只有超时或中断才退休旧实例，再允许下一份安装继续。

`PlayerPage` 移除旧实例的事件订阅，释放旧播放器，并为下一次安装创建独立原生实例。迟到的 create、设置数据源和初始化事件不能初始化新的分集。清理 PiP 标记，避免旧窗口消失后仍按后台画中画意图续播；明确重试可重新播放。保留当前重试上限、播放速度、观看进度、暂停意图及正常 PiP 连播复用。

## 取流取消与结果归属

每份会话拥有的取流请求携带独立 `requestId`，取消按请求、作品及分集身份匹配。预取转为前台继续共享原请求；被淘汰、关闭或退出的请求取消对应核心 context。退出时立即停止仍在解析的请求，已准备媒体继续存活到远程／原生播放器清理结束。

核心同时处理“取消先到、请求后派发”的情况。取消记录保留 75 秒以覆盖 Android 最大排队预算，播放取消记录至多 64 条、同时跟踪至多 8 份解析。已有搜索和目录取消也采用同一保留期。请求结束或客户端关闭会移除在途归属；关闭／取消后的解析不能重新发布播放会话或代理。

核心协议保持 3，并通过 `resolveCancellation: 1` 声明可选能力。缺少该能力的旧核心继续使用迟到结果保护；下载规划和其他普通解析不必传请求标识。

## Android 派发

每个引擎仍拥有独立客户端及三条联网工作线程。取消、释放和轻量状态读取使用独立控制线程，避免等待占满的联网线程。两个队列各有 32 项上限；排队超时会移除尚未运行的工作并只回复一次。

从进入桥接队列开始计算单调时钟预算，启动工作时将剩余期限交给 Go；不足核心最短期限时不再启动。核心继续拥有运行阶段的 context 期限；派发器不丢弃已经返回的核心结果，以免隐藏已创建的媒体资源。系统文件 IO 的退出仍取决于操作系统，不将此改动描述为所有本地 IO 都可被强行打断。

Android 初始化返回 `dispatchEnvelope: 1`，Flutter 随后发送小型派发信息及原始 JSON。完整 JSON 在工作线程解析；iOS 和旧桥接继续使用字符串参数。核对声明的方法与正文一致后才执行，完整请求和签名资料不进入用户提示。

## 验证

定向回归覆盖初始化事件缺失、create／setDataSource 不返回、超时后迟到结果、快速选集、退出、PiP 退休后禁止后台播放和明确重试恢复；会话回归继续验证前台接管预取、质量、文件和释放归属。

Android 的实际 Java 派发器通过 JVM 测试验证三条联网线程被阻塞时仍可取消、排队期限及剩余预算、队列容量、一次回复和引擎隔离。Kotlin／Java bridge 使用真实 Flutter embedding、Android API 36 和 gomobile 类编译。Go 通过带受控传输的真实 provider 调用验证取消中断 IO，并检查没有发布或遗留媒体会话；相关竞态检查通过。

最终本地验证：Flutter 全量 1015 项通过，零失败、零跳过，启用真实 FFmpeg、字体和既有性能场景；Go 全量 633 个测试／子测试通过，零失败，8 项既有可选联网巡检未启用；Python／JVM 工具回归 43 项通过。Flutter analyze、Dart 全项目格式、Go vet、相关 Go 竞态和差异检查通过。最终日志位于 `/tmp/guoguo-playback-reliability-*`，其中 Flutter 结果为 `flutter-final.jsonl`，Go 为 `go-full.jsonl`。

整包构建与交付状态以本批 PR HEAD 的工作流为准。设备 PiP、长时间连播及实体电视性能仍按既有设备清单验收；这些主机用例不代表真机耗时或故障发生频率。
