# AirPlay 会话重构（0.14.0+32）

用户反馈 0.13.2 换集停止再播放，退出重进后画面在手机、声音在电视。前两批修复没有正确表达系统路由的生命周期，本批替换该会话交接方式。范围是 AirPlay 的基础播放、切集、退出、重进及返回 iPhone；Google Cast／DLNA 保留已有会话与控制路径。

## 根因与交接约定

`AVPlayer.allowsExternalPlayback = false` 只关闭外部视频，不会让 `AVAudioSession.currentRoute` 的 AirPlay 音频路由变成本机。旧实现按准备状态过滤系统路由，新页面忽略仍选中的电视，因而允许本地视频配电视音频。逐集 reset／clear 又撤销外部视频意图，先关闭旧 relay 再安装新源，接收器连接及取流都可能被打断。

新页面先读取真实音频路由，仍选中电视时要求完整准备并直接安装可访问的 relay 地址，之后才允许播放。系统音频路由与真实外部视频分别报告，已连接标记只取实际外部视频。系统路由仍由用户在原生 AirPlay 列表选择；应用不借助录音类别或私有 API 强制输出扬声器。Apple 的 [系统路由](https://developer.apple.com/documentation/avfaudio/avaudiosession/currentroute) 与 [外部视频许可](https://developer.apple.com/documentation/avfoundation/avplayer/allowsexternalplayback) 是两项状态。

切集保留准备意图和外部视频许可，原生直接替换当前 item；Flutter 等待安装完成后关闭旧 relay。可有网络加载或接收器解码停顿，不能据此保证无缝播放，但不应断开会话或重新选电视。后台自动下一集、自动连播开关和最后一集边界沿用已实现逻辑。

退出先使旧请求失效，等待已经提交的安装，再由原生暂停、撤下 item，最后关闭 relay 和临时媒体。新页面读取当前系统路由并采用它。在原生列表选择 iPhone 后，才恢复原本本地视频、当前实际位置、速度和播放意图；不会把关闭外部视频当作音频已经返回。

音频已到电视但外部视频尚未接通时，手机显示等待而不继续展示本地视频。存在播放意图且 15 秒未确认外部视频则暂停、显示明确提示；暂停选择设备不计时，连接失败不使用普通视频自动恢复。重复点击复用安装，快速切集取消旧请求，迟到事件按源版本与地址核对。

## 原生边界

原生 `getAirPlayState` 可在第一项视频创建前查询路由，事件带当前源地址和版本。`releaseAirPlay` 的同步返回意味着旧媒体已经撤下，随后才允许清理 HTTP 服务。仅换集不会调用 release，不会重新弹路由列表。准备状态、有限媒体合成、HLS 渲染、重复结束过滤及真实结束位置兜底保留。

初始化检查当前 item 的 ready 状态，先从视频轨获取尺寸；外部播放已准备或路由已选中时，不依赖本机先展示画面，避免安装完成和准备投屏互相等待。原生暂停在初始化／完成阶段也确实暂停 AVPlayer，旧定位、速率修复和停顿恢复不能影响下一源。完整方法约定见 [原生修正说明](../patches/better_player_plus/README.md)。

## 验证与限制

自动化覆盖路由继承与退出重进、切回 iPhone 的进度／暂停、前后台切集、音频单独连接超时、关闭自动连播／最后一集、并发安装取消、延迟事件以及停止后清理顺序。Swift 策略回归和完整 iOS 编译由 CI 执行，完整 Flutter／Go 检查仍是交付门槛。原生依赖继续固定 1.4.1，受校验补丁只应用到独立构建副本。

这些验证不等同于第三方安卓电视 AirPlay 软件已通过真机验收。接收软件名称和版本尚未提供；应按 [设备清单](ios-device-checklist.md) 连续三集、退出重进和切回 iPhone 复测。
