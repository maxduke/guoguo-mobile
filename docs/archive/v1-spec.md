# 果果移动端首版规格

状态：主要产品范围已由需求访谈确认；技术可行性与设备兼容性尚未验证。

## 实施优先级更新

用户在开始实现后明确要求先聚焦 iOS，已有 iPhone、iPad 和 Sony 安卓电视。当前优先交付 iPhone / iPad；Android 工程保留，手机端适配与验收后置。Sony 电视的具体型号与接收协议尚未确认。GitHub 最终交付为用户账户下的私有仓库。

## 产品目标

构建独立运行的 Flutter 短剧应用，支持 iOS、Android 手机和平板。用户安装后直接选择站源、找剧与连续观看，无需维持电脑或业务服务器在线。首版按侧载、自签安装交付。

本规格中的“必须”表示交付要求，不表示已经实现。三类投屏设备均为期望覆盖目标，最终兼容矩阵必须有实测证据。

## 页面与视觉

| 入口 | 内容与行为 |
| --- | --- |
| 剧库 | 默认启动页，记住上次站源；红果、黄果、黄豆分别浏览，提供搜索、分类、榜单、推荐与继续观看入口 |
| 追剧 | 继续观看、收藏、观看历史；跨站汇总，标注来源并支持筛选 |
| 下载 | 下载中、已完成、批量操作、空间管理；跨站汇总并可筛选 |
| 设置 | 顶部图标进入；外观、播放偏好、移动数据开关、记录备份 |

- 手机底部三个主入口：剧库、追剧、下载。
- 平板采用多列海报、分栏详情等大屏布局；具体断点在设计阶段确定。
- 浅色使用暖白与墨绿，深色使用深灰与柔和绿色；支持跟随系统且默认启用。
- 播放器采用深色背景。

## 找剧与离线浏览

- 三个站源均为首版范围；同名作品不跨站合并。
- 输入搜索词时筛选当前站源缓存；提交搜索后联网补充。各站源实际搜索能力须单独验证。
- 断网时保留已缓存列表、封面与详情，明确提示离线。未缓存内容不能表现为已完整加载。
- 已下载分集可离线观看，未下载分集提示联网后播放。
- 推荐来源和榜单种类待调研；不将本地排序声称为真实站点榜单。

## 连续观看

- 上滑下一集、下滑上一集；提供选集面板，播完自动进入下一集。
- 点击暂停/继续、进度拖动、倍速选择、长按临时 2 倍速。
- 横屏播放、手势锁定、站源可用清晰度选择。
- 下一集预缓冲与真实观看历史分开，预缓冲不能生成观看记录。
- 必须支持系统画中画（PiP）。
- 必须支持在线投屏，争取覆盖 AirPlay、Google Cast、国内电视/盒子接收端；不包含本地下载视频投屏。
- 首版不做弹幕。

## 下载与网络

- 支持分集、整剧下载，展示进度，可取消、删除、暂停、恢复、失败重试、批量操作及管理空间。
- 下载完成后的分集无需联网即可播放。
- 后台尽量继续，被系统中断后保留任务，重新打开自动恢复；恢复须遵守网络偏好。
- 下载和下一集预缓冲默认仅限 Wi-Fi；切换到移动网络时暂停对应行为，两个权限可在设置中分别开启。
- 移动网络可在线播放。

## 个人记录

- 收藏和观看历史分别管理，不使用“想看 / 在看 / 已看”状态分类。
- 无需账号，保存到当前设备，手动导出、导入备份。
- 备份包含收藏、观看历史，不包含视频文件。

## 建议的边界规则（尚未由用户确认）

这些是用于后续设计的默认建议，不新增已确认承诺。

- 作品身份由站源与源内作品 ID 共同确定，分集同样保留来源；不按名称去重。
- 整剧下载只包含创建任务时已获取的分集，新集需用户再次发起下载。
- 导入采用合并，收藏去重；同一作品的观看记录按实际观看时间取较新记录，而非按最大进度取值。导入前显示摘要，损坏备份不修改现有记录。
- 手动暂停的任务不因重启而自动恢复；因网络限制或系统中断暂停的任务按网络偏好恢复。
- 返回列表保留滚动位置和筛选；切换站源后丢弃过期请求的界面更新，避免结果串站。
- 清理浏览缓存不删除收藏或完整下载；删除下载不删除观看历史。
- 手势锁定后保留明确解锁入口；长按结束恢复原倍速；选集面板打开时不触发上下滑切集。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 三站找剧 | 每站独立完成列表、详情、选集与真实播放；搜索是否联网及其失败状态明确 |
| 连续观看 | 选集、上下滑、自动下一集不串剧；离开再进入能续播，预缓冲不污染历史 |
| 网络切换 | 默认策略下 Wi-Fi 转移动网络停止下载与预缓冲，在线播放可继续 |
| 离线使用 | 已缓存页面可浏览，已完成下载可播放，其他内容提示联网 |
| 任务恢复 | 系统中断后任务仍在，重新打开按网络规则恢复；不能把重头下载伪装为断点恢复 |
| 记录迁移 | 导出后在另一设备导入，收藏及观看位置可恢复，视频无需放入备份 |
| 画中画 | 进入、退出、回到全屏后位置一致，不出现双音轨或重复播放 |
| 投屏 | 已验证设备完成发现、连接、播放及结束会话；验证进度交接与手机后台行为 |
| 手机与平板 | 深浅主题、横竖屏均可操作，海报比例正常，无溢出，分栏合理 |
| 异常状态 | 站源失败、链接过期、空间不足、空搜索结果均提供明确状态与适当恢复入口 |

性能验收需固定真实设备、媒体样本和网络条件后制定首帧与切集等待基线，不能用模拟数据替代真实播放结果。

## 实施顺序

1. **技术验证**：三站真实资源 → 手机播放 → 下载与恢复 → PiP → 投屏兼容矩阵。比较站源逻辑重写与 Go 核心复用，不提前锁定媒体库。
2. **界面与主流程**：建立 Flutter 手机/平板布局、主题与导航，串起找剧、观看、收藏和历史。
3. **完整能力**：下载管理、离线、备份、已验证的原生系统能力及投屏。
4. **设备验收与分发**：完成真实网络、进程中断、横竖屏和接收设备测试，生成 Android 安装包与 iOS 签名安装材料。

阶段顺序不缩减首版三个站源或其他已确认功能的交付范围。
