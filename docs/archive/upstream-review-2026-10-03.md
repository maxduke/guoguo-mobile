## D：保留、延期及不采用

1. **保留十八源身份，暂不跟随删除网果、发果。** 上游移除了注册、别名及解析分支；这不能证明其永久失效。本地旧备份解析遇到未知站源会报错。若日后停用，应隐藏入口并保留旧记录识别、收藏、历史、下载及导入兼容。
2. **饭果／星果 ID 编码不能直接替换。** 上游从 `id#source` / `id@简介` 改为 `id~base64url(payload)`，截断 payload 到 80 字符，并在原生目录缓存迁移。我们的收藏、历史、分集身份和下载均依赖旧 key。应先定义稳定业务 ID 与附加元数据，兼容旧 ID，再迁移所有持久化引用；不能只复制目录迁移函数。
3. **星果全量遍历默认不采用。** 上游遍历资源 ID 1..5200，每批 40、并发 4；单项错误/panic 被忽略。对手机流量、电量和错误完整性均不合适。可以吸收正常分类页大小与分页改动，但保留失败可见、按需加载。
4. **不采用 TLS `InsecureSkipVerify` 自动回退。** 上游 `network_media.go` 在黄果 AI 媒体证书错误后克隆不校验证书的客户端。这是明确的连接校验退让，不是普通重试优化；保留有效证书、可信线路和失败提示。
5. **Android SurfaceView / media_kit 暂不迁移。** 新增 Dart 平台视图和 Kotlin Surface/JNI 引用管理，依赖 media_kit helper 反射、mpv 属性、纹理回退，延迟 5 秒释放引用。属于播放器后端项目，需要 Android 单独性能和生命周期验收；不能据此替换 iOS BetterPlayer/AVPlayer、PiP、AirPlay 或提前开播。
6. **TV 焦点导航作为独立里程碑。** 上游大幅增加 `RemoteRow/List/Grid` 边界跳转、焦点恢复、电视下载操作和设置弹窗，覆盖首页、详情、选集、收藏历史、下载、用户、互联等。适合将来 Android TV，但当前不是手机小修，不能只复制控件后宣称 TV 可用。
7. **弹幕延期但保留候选。** 新增短码表情转换、截断兼容和仅在弹幕边界/状态变化时通知；基础弹幕在此前基线已存在。本地还没有移动端弹幕接口/UI，需单独接入可取消、有界、分集隔离的时间轴，不能仅移植表情文件。
8. **多用户、启动登录、局域网同步、Emby、本地媒体合并暂不扩张。** 本轮相关变动多数是入口/电视焦点/通知适配，基础功能早已在上游存在。启动登录开关也不是相对 `ffddc0b` 的新增核心行为。保持单机“收藏/历史”的产品定义。
9. **不移植品牌和发行变体。** 24 个二进制资源及图标生成更新属于上游品牌；保留果果名称、图标、应用标识和升级路径。上游红果版/全源版也不适合直接引入。
10. **不覆盖依赖锁文件。** 上游新增直接 wakelock 和 XZ 依赖，锁文件 Dart 下限升到 3.13，且更新了数个传递依赖；按实际采用功能独立解析，避免无关 SDK/播放器升级。

## 搬入前必须修正的具体边界

这些是固定提交中的静态证据，尚未执行动态复现：

- [猫果请求层](https://github.com/maxduke/guoapp/blob/5999e469e1281e55dcf603c980f83cd0ba00206d/native/core/provider_duanju_api.go#L120) 仍用非负数字正则过滤分类，而新增 `validMaoguoCategory` 接受负 ID；需要端到端一致。另需覆盖 `next_id=0`、非连续游标、重复页和末页。
- [推荐缓存构造](https://github.com/maxduke/guoapp/blob/5999e469e1281e55dcf603c980f83cd0ba00206d/lib/player_screen.dart#L2208) 没有传 `page.hasMore`，默认 false，可能把第一页缓存标成完整搜索结果。复用到首页前必须修复。
- [首页进度轮询](https://github.com/maxduke/guoapp/blob/5999e469e1281e55dcf603c980f83cd0ba00206d/lib/home_screen.dart#L614) 缺少推荐轮询中已有的在途防重入；原生进度接口只读红果 pending，不能对所有源宣称支持流式进度。
- [无扩展名小媒体分支](https://github.com/maxduke/guoapp/blob/5999e469e1281e55dcf603c980f83cd0ba00206d/native/core/app_stream.go#L506) 透传 206 时只设置类型与长度，没有透传 `Content-Range`；已有上游范围测试不能替代完整响应头契约。保留我们现有 Range/HEAD 行为并补边界样例。
- `loadSourceCatalogCategories` 用 engine 级布尔值延迟写盘、defer 中忽略最终写盘错误。移植批量写盘时需用有明确所有权的批次/计数和可返回错误，覆盖多源并发及磁盘失败。
- `VideoSurfaceHost._attachSurface` 是串行队列中的任务，异常后调用 `_fail`，而 `_fail` 又入同一队列并等待释放，存在等待自身完成的风险。即使未来迁移 Android 后端，也应先修复失败路径，不把“有纹理回退函数”当成回退已可靠。

## 工程流程和验证资产

- 上游 Android 构建新增原生库清单，校验平台、架构、站源变体和包内库哈希。可以把“防止打包旧原生核心”思想用于我们的 gomobile AAR / XCFramework，但补源码/桥接版本身份；仅库与旁边清单一致不代表匹配当前源码。落点 `scripts/build_core.sh`、发布校验和 CI。
- 上游导入脚本新增必填签名 ZIP URL、中文路径编码、保留查询字节、HTTPS 重定向限制、日志不保存签名；有配套 27 项定向测试。可借鉴差异预览和来源锁定，但不使用它的整仓自动导入/发版流程同步 mobile。
- 新增测试资产覆盖：搜索部分结果/缓存、榜单来源、错误卡片、库导入幂等与 XZ、无扩展名媒体、同源凭证与清晰度回退、黄果线路/身份、牛果分类、启动/播放器入口/Surface 生命周期/帧耗时。应随采用功能移植等价测试，保留我们已有 iOS PiP、渐进 HLS、下载恢复和取消回归。
- 帧耗时与 Surface 生命周期 integration tests 主要是设备测量脚手架，部分依赖外部 HOME/返回操作；它们存在不代表上游已完成真机验收，也不能证明移动端必然更快。
