# 播放会话整理（0.11.1+23）

PR #6 已合并到 main（`1d9a2dc`），首段预取分支及工作区已清理。本批继续执行 [融合计划](app-fusion.md) 中的播放器整理，从会话资源和异步交接开始，适配既有 BetterPlayer／AVPlayer。

## 资源与交接

新增 `PlaybackSessionController`，统一拥有每集的解析结果、媒体准备任务、临时文件、准备计时及待使用的备用资源。后台预取仍只解析地址和读取有界首段；选中时接管同一任务并撤销后台期限，再按当前设置准备加密媒体。沿用远程地址两分钟有效期和凭证到期前五秒重新解析的规则，完整本地文件继续复用。

清晰度选择和必须完整准备的标记随会话保留。离线优先使用已下载文件；没有文件时保留现有明确错误。续播、兼容回退以及 Wi-Fi／蜂窝偏好沿用原策略，首段缓存预算和原生协议 3 不变。

每次激活或切集使上一播放轮次失效。准备完成后和提交原生源前均检查轮次；原生设置保持串行，过时的排队请求不执行，已经开始的设置返回后不得触发旧集开播。设置失败会传回现有恢复逻辑，同时疏通队列供后续设置使用。关闭会话使当前及排队请求失效。

准备失败、缓存淘汰和退出统一取消任务并释放媒体会话。补齐尚未消费的备用资源被新重试覆盖、移出保留范围，以及关闭后收到备用资源时的释放。取消期间迟到的解析／准备结果只清理自己的资源，不能淘汰后来的缓存；取消失败仍保留临时文件直至原生写入停止，沿用既有清理边界。

## 抽取边界

页面继续管理 BetterPlayer 对象、控件、观看位置、暂停意图、恢复预算以及生命周期／PiP 事件。控制器通过回调读取本地文件和当前准备偏好，不依赖 Flutter 页面状态，也不订阅系统事件。本批完成资源准备与源交接的抽取，后续再收拢恢复和生命周期协调，不能视为播放器架构已全部重构。

没有替换播放内核，也没有改变提前开播实验的默认值。异步交接回归不能证明 iOS 系统事件顺序、设备首帧或耗电表现。

## 验证

独立控制器回归覆盖后台加密媒体延迟整理、准备中的前台接管、关闭后的迟到解析、淘汰后的迟到整理、备用资源所有权、远程缓存及授权过期、本地离线播放、清晰度与完整准备策略、串行交接、原生设置失败及关闭时的排队请求。页面集成回归另外覆盖连续快速切集和原生设置失败后的备用线路恢复，沿用既有 PiP／后台／暂停／取消检查。
