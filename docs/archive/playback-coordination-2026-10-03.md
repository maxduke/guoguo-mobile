# 恢复与生命周期协调（0.11.2+24）

PR #7 已合并到 main（`891a3da`），该提交的 Flutter／Go 检查与 iOS 无签名构建通过，原分支及工作区已清理。本批继续执行 [融合计划](app-fusion.md) 的播放器整理，在既有播放会话控制器之上抽取恢复与后台交接。

## 恢复与意图

新增 `PlaybackRecoveryController`，集中持有每集的有限恢复预算、卡顿观察状态及正在恢复的播放轮次。沿用最多三次自动尝试、优先备用线路和最多一次重新解析；只有选中新分集或手动重试重置预算。原生暂停及备用线路请求期间拒绝重复恢复，迟到结果只释放自己的媒体会话；旧轮次结束不能清除新轮次的恢复标记。兼容准备使用同一互斥边界，避免同时进入多个准备流程。

新增 `PlaybackLifecycleController`，集中管理前台／PiP 状态、用户播放意图、延迟开播、手动 PiP 进入前的状态，以及后台挂起时保存的进度。生命周期和原生 PiP 通知可按不同顺序到达：及时启动保留当前提前开播任务和下一集准备，超过 800 ms 仍未启动则取消临时任务；迟到启动或回到前台走完整准备，并保持进度和暂停。定时回调校验播放轮次，切集、关闭和前台返回后不清理新会话。

补充回归复现了一个原有边界：提前开播失败后等待原生取消，用户在这段时间关闭 PiP。旧代码先记录了继续播放，取消完成后重新使用该值，回到前台时又开播。本批在兼容恢复开始时捕获意图，取消完成后核对期间是否有新的意图；关闭 PiP 或明确暂停优先，原生设置期间的临时暂停不覆盖原有意图。回归同时检查完整视频、观看位置及原生播放调用，修正前确实失败。

## 适配边界

两个控制器通过当前媒体快照和明确的效果回调协调，不持有 Widget、BetterPlayer 或系统订阅。页面继续接收系统事件、显示控件、执行原生播放与兼容视频准备，并管理观看记录、预取调度及手势。本批没有替换 AVPlayer／BetterPlayer，提前开播实验、首段预取预算、蜂窝偏好与协议 3 均沿用现状。
